Case Study 1 — Convolutional Neural Networks (CNNs)

Deep Learning from First Principles · Deep Learning Architectures: Architectures · Case Study 1

Our guiding question: How can we take the same neurons we learned in micrograd and reorganize them so they understand images?

We'll build a CNN from the ground up, without abandoning anything we've learned about weights, biases, activations, loss functions or backpropagation.

Our case study: Recognizing handwritten digits

We'll use MNIST, a classic dataset of handwritten digits.

Each image is 28 × 28 pixels, with one grayscale channel. There are 60,000 training images, 10,000 test images and 10 possible labels (0–9).

Our objective is straightforward: given an image, predict which digit it contains.

By the end of this case study, we'll understand the entire journey:

28 × 28 pixel image

Convolutional layers

Learn local patterns using shared weights

Spatial feature extraction

ReLU, pooling, and progressively richer features

Classification layer → 10 logits

Cross-Entropy → Backpropagation → AdamW

1. Why isn't our existing MLP ideal for images?

Remember our original neuron:

z=w1x1+w2x2+⋯+wnxn+bz=w_1x_1+w_2x_2+\cdots+w_nx_n+b

An MLP could take an entire 28 × 28 image, flatten it into 784 numbers, and pass them into a fully connected layer.

MLP approach

Flatten image → fully connected neurons

CNN approach

Inspect neighborhoods → produce spatial feature maps

An MLP can learn image classification, but its fully connected layers do not inherently exploit the image's two-dimensional structure.

A conventional CNN introduces two useful assumptions:

  • Local connectivity: Nearby pixels can form meaningful patterns such as edges, corners and curves.
  • Weight sharing: The same learned pattern detector can be applied at different positions in the image.

That second idea is the major architectural innovation.

An MLP learns weights for connections between specific input and output positions. A CNN reuses the same filter weights across many spatial positions.

Let's see exactly what that means.

2. A convolution is still a neuron calculation

This is the connection I want you to understand most clearly.

Our original neuron calculates:

z=w1x1+w2x2+⋯+wnxn+bz=w_1x_1+w_2x_2+\cdots+w_nx_n+b

A convolutional filter does essentially the same thing, except its inputs are taken from a small spatial neighborhood rather than from the entire image.

Let's construct a tiny example.

A 5 × 5 image and a 3 × 3 filter

Imagine a five-pixel-wide image containing a vertical white line.

We'll create a filter designed to respond to that vertical line.

At the center, the selected input patch is:

[010010010]\begin{bmatrix} 0&1&0\\ 0&1&0\\ 0&1&0 \end{bmatrix}

Our filter has the same pattern. Multiplying corresponding entries and summing gives:

z=1+1+1=3z=1+1+1=\boxed{3}

The filter moves to the next location and reuses those same nine weights.

That's convolution's central idea.

Connection to micrograd

A convolutional output is still a weighted sum plus bias, optionally followed by an activation function.

The difference is that its weights are shared across many spatial locations.

Technically, the operation PyTorch calls convolution is cross-correlation, because it doesn't reverse the kernel. The distinction doesn't affect the learning intuition here.

3. A filter produces a feature map, not just one number

This is where CNNs differ significantly from our original MLP.

In a normal fully connected layer, one neuron produces one output for each example.

In a convolutional layer, one filter produces an entire spatial map of outputs.

In our toy example:

5 × 5

Input

3 × 3

Filter

3 × 3

Feature map

Why did the spatial size shrink from 5 × 5 to 3 × 3?

With stride 1 and no padding, the 3 × 3 filter fits in three horizontal and three vertical positions.

This leads us to two important terms:

Concept Meaning Effect
Stride How many pixels the filter moves each step Larger stride produces fewer output positions
Padding Extra pixels added around image boundaries Can preserve spatial size

For a 3 × 3 filter, stride 1, and padding 1, a 28 × 28 input produces a 28 × 28 feature map.

Without padding, it would produce 26 × 26.

The general output-size formula for a standard convolution, with dilation 1, is:

Hout=⌊H+2P−KS⌋+1H_{\text{out}}= \left\lfloor\frac{H+2P-K}{S}\right\rfloor+1

Where HH is input height, PP is padding, KK is kernel size, and SS is stride. The same formula applies to width.

We won't need to calculate this manually every time, but understanding the relationship helps us trace tensor shapes.

4. Multiple filters and multiple channels

So far, we used one filter.

But one filter can detect only one kind of pattern at a time.

What if we want the network to learn different useful patterns?

We introduce multiple filters.

Schematic: eight different filters applied to one grayscale input produce eight output channels.

For example, different filters might learn to respond to horizontal strokes, vertical strokes, curves, corners or other useful local patterns.

We don't program these detectors manually. Their weights are initialized and learned through backpropagation.

How many parameters do eight filters have?

Each 3 × 3 filter has nine weights, plus one bias.

Eight filters give:

8(3×3+1)=808(3\times3+1)=\boxed{80}

And here's the surprising part:

Those 80 parameters are sufficient to produce eight full 28 × 28 feature maps.

Why? Because the same weights are reused at every position.

What happens in the second convolutional layer?

Suppose the input now contains eight feature maps.

We want 16 output feature maps.

Each new filter must examine all eight input channels, not just one.

8 input feature maps

One filter has shape 8 × 3 × 3

One 3 × 3 weight slice for each input channel

One output feature map

Repeat with 16 separately learned filters → 16 output maps.

The parameter count is therefore:

16(8×3×3+1)=116816(8\times3\times3+1)=\boxed{1168}

Important: A filter combines information across all its input channels, then produces one output channel.

This will be extremely useful when we get to more complex architectures.

5. Pooling: Reducing spatial dimensions

Our CNN now has many feature maps. But do we need to preserve every spatial location through the entire network?

Not necessarily.

Pooling summarizes small neighborhoods.

A common choice is Max Pooling, which keeps the largest value in each neighborhood.

With 2 × 2 max pooling and stride 2:

  • 28 × 28 becomes 14 × 14.
  • 14 × 14 becomes 7 × 7.
  • The number of channels stays unchanged.

Max pooling has no learned weights or biases.

During backpropagation, its gradient is routed to the input position that supplied the maximum value (with tie handling determined by the implementation).

Pooling reduces computation and creates some tolerance to small spatial changes. But it also discards information.

7. But how does backpropagation work through convolution?

This is an essential connection to micrograd.

It works using exactly the same chain rule.

The key difference is that one convolutional weight is reused at many spatial locations.

Suppose a filter weight ww influences 784 output positions.

During the forward pass, that same value is used at all those positions.

During backpropagation, the gradient for that weight combines its contributions from all positions where it was used.

Conceptually:

∂L∂w=∑spatial positions p∂L∂zp∂zp∂w\frac{\partial L}{\partial w} = \sum_{\text{spatial positions }p} \frac{\partial L}{\partial z_p} \frac{\partial z_p}{\partial w}

And when we process a batch, the gradient also aggregates contributions across examples, with the scaling determined by the loss reduction.

Shared convolution weight ww

Backpropagation combines gradient contributions

One gradient for the shared parameter

Optimizer updates w once per step

This is why weight sharing is so powerful.

A single parameter can learn from evidence at many different image positions.

There is no new backpropagation algorithm. Autograd simply follows the enlarged computational graph.

8. Let's implement the CNN in PyTorch

First, the architecture itself.

import torch
import torch.nn as nn
import torch.nn.functional as F

class DigitCNN(nn.Module):
    def __init__(self):
        super().__init__()

        # First convolutional layer
        self.conv1 = nn.Conv2d(
            in_channels=1,
            out_channels=8,
            kernel_size=3,
            padding=1
        )

        # Second convolutional layer
        self.conv2 = nn.Conv2d(
            in_channels=8,
            out_channels=16,
            kernel_size=3,
            padding=1
        )

        # Spatial downsampling
        self.pool = nn.MaxPool2d(2)

        # Final classification layer
        self.head = nn.Linear(16 * 7 * 7, 10)

    def forward(self, x):
        # (B, 1, 28, 28)
        x = self.pool(F.relu(self.conv1(x)))

        # (B, 8, 14, 14)
        x = self.pool(F.relu(self.conv2(x)))

        # (B, 16, 7, 7)
        x = torch.flatten(x, start_dim=1)

        # (B, 784)
        logits = self.head(x)

        # (B, 10)
        return logits

model = DigitCNN()

X = torch.randn(32, 1, 28, 28)

print(model(X).shape)
# torch.Size([32, 10])

print(sum(p.numel() for p in model.parameters()))
# 9098

Look at this line:

x = self.pool(F.relu(self.conv1(x)))

It's simply three successive operations:

Weighted sums (Conv)

ReLU

MaxPool

The only new operation compared with our MLP is the structured, spatially shared weighted sum and the spatial pooling. We already understand ReLU.

9. Training the CNN on MNIST

Now we connect the new architecture to our original training loop.

Prepare the dataset

We'll use 55,000 images for training and 5,000 for validation, keeping MNIST's official 10,000-image test set separate.

from torchvision import datasets, transforms
from torch.utils.data import DataLoader, random_split

torch.manual_seed(42)

transform = transforms.ToTensor()

full_train = datasets.MNIST(
    root="./data",
    train=True,
    download=True,
    transform=transform
)

train_data, val_data = random_split(
    full_train,
    [55000, 5000],
    generator=torch.Generator().manual_seed(42)
)

train_loader = DataLoader(
    train_data, batch_size=64, shuffle=True
)

val_loader = DataLoader(
    val_data, batch_size=256, shuffle=False
)

print(train_data[0][0].shape)
# torch.Size([1, 28, 28])

ToTensor() converts the image into a floating-point tensor with pixel values in [0,1]. The dataset downloads on the first run if it isn't already available locally.

Train and validate

The following code uses the DigitCNN class and data loaders defined above.

# Use Apple GPU, NVIDIA GPU, or CPU
if torch.backends.mps.is_available():
    device = torch.device("mps")
elif torch.cuda.is_available():
    device = torch.device("cuda")
else:
    device = torch.device("cpu")

model = DigitCNN().to(device)

loss_fn = nn.CrossEntropyLoss()

optimizer = torch.optim.AdamW(
    model.parameters(),
    lr=0.001,
    weight_decay=0.0001
)

history = {"train": [], "val": []}

for epoch in range(3):

    # -------- Training --------
    model.train()
    total_loss = 0.0

    for images, labels in train_loader:
        images = images.to(device)
        labels = labels.to(device)

        optimizer.zero_grad()

        # Forward
        logits = model(images)

        # Loss
        loss = loss_fn(logits, labels)

        # Backward
        loss.backward()

        # Update
        optimizer.step()

        total_loss += loss.item() * images.size(0)

    train_loss = total_loss / len(train_data)

    # -------- Validation --------
    model.eval()
    val_loss = 0.0
    correct = 0

    with torch.no_grad():
        for images, labels in val_loader:
            images = images.to(device)
            labels = labels.to(device)

            logits = model(images)
            loss = loss_fn(logits, labels)

            val_loss += loss.item() * images.size(0)
            correct += (logits.argmax(1) == labels).sum().item()

    val_loss /= len(val_data)
    accuracy = correct / len(val_data)

    history["train"].append(train_loss)
    history["val"].append(val_loss)

    print(
        f"Epoch {epoch+1}: "
        f"train_loss={train_loss:.4f}, "
        f"val_loss={val_loss:.4f}, "
        f"val_accuracy={accuracy:.2%}"
    )

The training loss and validation accuracy will come from the actual model run, not predetermined example results.

11. Why stack convolutional layers?

Our first convolution sees small patches of raw pixels.

The next convolution sees patches of the first layer's feature maps.

This allows the second layer to combine simple local patterns into more complex ones.

Raw pixels

Brightness values, strokes

Early convolutional features

Potential edges, directions, local contrasts

Deeper convolutional features

Potential combinations of strokes and curves

Classification layer

Combine features to score digits 0–9

This is called hierarchical feature learning.

We also get an important concept called the receptive field: the region of the original image that can influence a particular feature-map value.

With stacked convolutions, the receptive field grows. A deeper feature can depend on a larger region of the original image than a feature from the first layer.

This helps the network progressively combine local information into broader patterns.

Let's compare our CNN to a simple MLP with one hidden layer of 128 neurons.

Trainable parameter comparison

The examples have different layer structures and capacities, so this is a parameter-count comparison, not a controlled accuracy or efficiency benchmark.

The CNN uses fewer parameters in this particular comparison because its learned filters are small and reused across the image.

The deeper advantage, however, isn't merely fewer parameters. It's the inductive bias that local spatial patterns matter and can be useful at different locations.

This makes CNNs particularly suitable for image-like data, although the same principles also apply to audio signals, time series and other structured grids.

Final mental model — What actually makes a CNN different?

  1. The core neuron hasn't changed.
z=∑iwixi+bz=\sum_iw_ix_i+b

Weighted sums, activations and trainable parameters still form the foundation.

  1. Connectivity has changed. A convolutional output depends on a local region and the input channels, rather than all spatial positions in the image.
  2. Weights are shared across positions. One learned filter is applied repeatedly across the image, producing an entire feature map.
  3. Layers build hierarchical spatial representations. Convolutions, nonlinearities and downsampling allow increasingly broad image patterns to influence deeper features.
  4. The training mechanism remains the same. Forward → Loss → Backward → Optimizer → Repeat.

That completes our first architectural case study.

Next architecture: Recurrent Neural Networks (RNNs). We'll begin with a very different problem: what happens when input order matters and a network needs to carry information from one time step to the next?

Our central question will be: Can we reuse the same neural network across time, while allowing its previous outputs to influence what it computes next?

A convolution is still a local weighted sum. Two refinements make the picture precise.

1. We haven't replaced neurons — we've reorganized their operations

In an MLP, a neuron takes a weighted sum of its inputs.

In a CNN, each convolutional output also computes a weighted sum, but only over a local spatial region, using weights shared across different positions.

So convolutional filters are still performing neuron-like computations.

2. Your CNN pipeline is correct

Using our MNIST example:

Input image

1 × 28 × 28 (channels × height × width)

8 convolutional filters (3 × 3)

8 × 28 × 28 feature maps

ReLU → MaxPool

8 × 14 × 14

16 convolutional filters (3 × 3)

16 × 14 × 14 feature maps

ReLU → MaxPool

16 × 7 × 7

Flatten → Fully connected Linear layer

784 inputs → 10 outputs

10 logits → Softmax probabilities

Digit classes 0–9

One terminology correction: a fully connected layer and a Linear layer are the same thing in this context. You don't necessarily need another Linear layer after it.

The last Linear layer produces however many output values the task requires. For MNIST, that's 10.

Also, remember that ReLU and pooling aren't mandatory after every convolution, and modern CNNs don't always use Flatten + Linear at the end. That's just the straightforward architecture we're learning.

The single most important takeaway:

An MLP primarily processes feature vectors through dense connections. A CNN processes spatially structured feature maps using local, shared-weight connections. Both ultimately use the same weighted sums, nonlinearities, loss functions and backpropagation.

And yes — you can stack as many convolutional layers as the architecture requires, subject to computational resources, spatial dimensions, and design choices.

Case Study 2 — Recurrent Neural Networks (RNNs)

Deep Learning from First Principles · Deep Learning Architectures: Architectures · Case Study 2

Our guiding question: How can we take the same neural network we learned in micrograd and give it the ability to remember information from earlier inputs?

In our previous case study, CNNs introduced spatial weight sharing: the same filter is reused at different positions in an image.

Now we'll introduce temporal weight sharing: the same neural network is reused at different positions in a sequence, while carrying information from earlier positions.

Our case study: Detecting a pattern in a sequence

Imagine a sequence of binary values:

Sequence A

Contains the consecutive pattern 1 → 0 → 1

Sequence B

Does not contain the consecutive pattern

We want a neural network to read the sequence and predict:

  • 1 if the pattern 101 appears anywhere.
  • 0 otherwise.

This task gives us a simple way to understand why keeping information from earlier time steps is useful.

By the end, we'll construct:

Sequence → Recurrent hidden states → Final prediction → BCE loss → Backpropagation through time.

1. Why do we need something beyond an MLP or CNN?

An MLP could flatten a fixed-length sequence and learn to classify it. A 1D CNN could also learn this local pattern effectively.

But consider sequences of different lengths, arriving one element at a time.

We'd like a network that can:

  1. Read an element.
  2. Combine it with what it has seen previously.
  3. Update its internal representation.
  4. Move to the next element using the same learned parameters.

That's precisely what an RNN is designed to do.

The architectural difference:

Ordinary MLP

Input x

NN

Output y

Current output is a function of the supplied input.

Recurrent NN

Current output also depends on the hidden state carried from earlier steps.

The new idea is recurrence: the network feeds an internal representation from one time step into the next.

2. The RNN is still made of familiar neuron operations

Our MLP neuron computes:

h=tanh⁡(Wxx+b)h=\tanh(W_xx+b)

An RNN extends that computation:

ht=tanh⁡(Wxxt+Whht−1+b)\boxed{h_t=\tanh(W_xx_t+W_hh_{t-1}+b)}

Only one new component has appeared: Whht−1W_hh_{t-1}.

Let's unpack it.

Symbol Meaning
xtx_t Input at the current time step
ht−1h_{t-1} Hidden state from the previous time step
WxW_x Weights applied to current input
WhW_h Weights applied to previous hidden state
bb Bias
hth_t New hidden state

A hidden state is just a vector of numbers. It isn't a separate memory database or a special kind of neuron.

The RNN takes the current input and its previous hidden state, performs weighted sums, applies an activation, and produces an updated hidden state.

That's remarkably close to micrograd.

3. One RNN cell, reused through time

Let's unfold the RNN across four time steps.

An RNN unrolled through time. The boxes represent repeated uses of one shared cell, not four separately parameterized networks.

At each step:

h1=tanh⁡(Wxx1+Whh0+b)h2=tanh⁡(Wxx2+Whh1+b)h3=tanh⁡(Wxx3+Whh2+b)h4=tanh⁡(Wxx4+Whh3+b)\begin{aligned} h_1&=\tanh(W_xx_1+W_hh_0+b)\\ h_2&=\tanh(W_xx_2+W_hh_1+b)\\ h_3&=\tanh(W_xx_3+W_hh_2+b)\\ h_4&=\tanh(W_xx_4+W_hh_3+b) \end{aligned}

Notice three things:

  • The input xtx_t changes at every time step.
  • The hidden state evolves as the sequence is processed.
  • The weight matrices remain exactly the same at every time step.

This is temporal weight sharing.

Usually we initialize h0h_0 to zeros for each new independent sequence. It can also be supplied explicitly or made learnable in more specialized designs.

Does a longer sequence create more parameters?

No.

If we process 10 steps instead of 4, we perform more computations, but reuse the same parameters.

That's exactly analogous to a CNN reusing its filter weights across different image positions.

4. Let's calculate one RNN forward pass manually

Before building a complete RNN, let's simplify it to one input feature and one hidden neuron.

We choose:

ht=tanh⁡(1⋅xt+0.5⋅ht−1)h_t=\tanh(1\cdot x_t+0.5\cdot h_{t-1})

Here:

  • Input weight = 1
  • Recurrent weight = 0.5
  • Bias = 0
  • Initial hidden state h0=0h_0=0

These are illustrative weights, not trained ones.

Let's process the sequence [1, 0, 1, 0, 1].

At time step 1:

h1=tanh⁡(1+0.5(0))≈0.7616h_1=\tanh(1+0.5(0))\approx0.7616

At time step 2, even though the input is zero:

5. What exactly is inside an RNN cell?

An RNN cell contains two familiar linear transformations followed by an activation.

So an RNN isn't an entirely new mathematical object.

It's an ordinary neural-network computation with an extra input coming from its own previous hidden state.

How many trainable parameters?

Suppose:

  • Input features per time step: D=1D=1
  • Hidden neurons: H=16H=16

A conceptual RNN cell has:

Wx:(16,1),Wh:(16,16),b:(16)W_x:(16,1),\quad W_h:(16,16),\quad b:(16)

That's:

16+256+16=28816+256+16=\boxed{288}

However, PyTorch's standard nn.RNN stores two separate bias vectors, one for the input transformation and one for the recurrent transformation.

So PyTorch's count is:

16+256+16+16=30416+256+16+16=\boxed{304}

The two biases are added together mathematically during the recurrent computation.

If we also use a final Linear layer mapping 16 hidden values to one prediction:

16+1=1716+1=17

Our complete RNN classifier therefore has:

304+17=321 parameters\boxed{304+17=321\text{ parameters}}

Whether our sequence has 5, 10 or 100 time steps, this number stays 321.

8. Let's build the RNN ourselves first

Before using nn.RNN, we'll construct the recurrent computation from familiar PyTorch linear layers.

import torch
import torch.nn as nn

class SimpleRNNCell(nn.Module):
    def __init__(self, input_size, hidden_size):
        super().__init__()

        self.input_layer = nn.Linear(
            input_size, hidden_size
        )

        self.hidden_layer = nn.Linear(
            hidden_size, hidden_size,
            bias=False
        )

    def forward(self, x_t, h_previous):
        return torch.tanh(
            self.input_layer(x_t)
            + self.hidden_layer(h_previous)
        )

cell = SimpleRNNCell(
    input_size=1,
    hidden_size=16
)

# Batch of 2 sequences, 3 steps each
X = torch.tensor([
    [[1.], [0.], [1.]],
    [[0.], [1.], [0.]]
])

# Initial hidden state
h = torch.zeros(2, 16)

# Reuse the SAME cell at every time step
for t in range(3):
    x_t = X[:, t, :]
    h = cell(x_t, h)
    print(f"Step {t+1}:", h.shape)

# Final state: (2, 16)

Pay special attention to:

h = cell(x_t, h)

That's the essence of a recurrent neural network.

The same cell receives the new input and its previous hidden state. Its weights are reused at every iteration.

The code is almost identical to the MLP operations you already learned.

9. Build the actual RNN classifier

Now we'll use PyTorch's built-in implementation.

import torch
import torch.nn as nn

class SequenceRNN(nn.Module):
    def __init__(self):
        super().__init__()

        self.rnn = nn.RNN(
            input_size=1,
            hidden_size=16,
            num_layers=1,
            nonlinearity="tanh",
            batch_first=True
        )

        self.classifier = nn.Linear(16, 1)

    def forward(self, x):
        all_states, final_state = self.rnn(x)

        # final_state shape: (1, B, 16)
        h_last = final_state[-1]

        # One logit per sequence
        logits = self.classifier(h_last)

        return logits

model = SequenceRNN()

X = torch.randn(32, 10, 1)

logits = model(X)

print(logits.shape)
# torch.Size([32, 1])

print(sum(p.numel() for p in model.parameters()))
# 321

batch_first=True tells PyTorch that the input layout is (batch, time, features).

An important subtlety: the final hidden-state tensor is still organized as (num_layers, batch, hidden_size) for a unidirectional RNN, regardless of batch_first.

The temporal computational graph is unrolled for backpropagation, even though the same cell parameters are reused at every time step.

If the loss is computed from h4h_4, its gradient can influence the computations at h3h_3, h2h_2, and h1h_1, because each later state depends on previous states.

13. The problem with vanilla RNNs: Long-term memory

Remember our final foundation lesson on vanishing and exploding gradients?

An RNN repeatedly transforms the hidden state:

ht=tanh⁡(Wxxt+Whht−1+b)h_t=\tanh(W_xx_t+W_hh_{t-1}+b)

During backpropagation through time, the gradient involves repeated Jacobian multiplications.

Across long sequences, those multiplications can cause gradients to become extremely small or extremely large.

Here's a simplified illustration where each backward step scales a gradient by 0.6.

An event that occurred many steps earlier may have very little influence on the learning signal reaching those early computations.

This can make long-range dependencies difficult for a basic RNN to learn.

For example, imagine a model reading:

The book that I borrowed from the library many weeks ago, after several recommendations from friends, was excellent.

To predict or interpret the verb agreement, the model may need information about "book" from much earlier in the sequence.

A basic RNN can theoretically preserve useful information, but learning to do so over long distances can be difficult.

This is one major reason why LSTMs and GRUs were developed.

They add learnable mechanisms that control which information is preserved, updated or forgotten.

We won't introduce their mathematics yet. That's our next architecture.

Final mental model — What makes an RNN different?

  1. The neuron is still familiar. Weighted sums, biases and activation functions remain the foundation.
  2. Each computation receives two sources of information. The current input xtx_t and the previous hidden state ht−1h_{t-1}.
  3. Weights are shared through time. Processing a longer sequence doesn't create more parameters.

We've now discovered the limitation that naturally motivates the next architecture.

A basic RNN has memory, but its hidden state is repeatedly transformed. Learning which information to preserve across long sequences can be difficult.

We'll keep this same RNN as our baseline and build the LSTM around it, one gate at a time.

The hidden state is what makes the recurrence work. Two refinements follow.

1. The neuron operation now includes the previous hidden state

In an ordinary MLP:

In an RNN:

ht=tanh⁡(Wxxt+Whht−1+b)\boxed{h_t=\tanh(W_xx_t+W_hh_{t-1}+b)}

The additional term Whht−1W_hh_{t-1} allows previous information to influence the current computation.

Importantly, the hidden state is usually a vector, not just one value.

Three important distinctions

  • A batch can contain multiple sequences. We process their corresponding time steps together using tensor operations.
  • We update parameters after processing the batch, not after every time step, in our standard sequence-classification setup.
  • The hidden state normally resets for each independent sequence or batch. We don't automatically pass the final hidden state of one unrelated sequence into the next. Stateful RNNs are a special case.

One further clarification: the final hidden state is used for prediction in our case study. Other RNN tasks can produce predictions and calculate losses at every time step.

The mental model: An RNN is an ordinary neural network repeatedly applied across time, with its previous hidden state serving as an additional input. The same parameters receive gradient contributions from all relevant time steps and are updated together.

This is exactly the foundation we need for LSTMs, where the main innovation is controlling that memory using learnable gates.

5. Why do LSTMs help with vanishing gradients?

Remember our previous RNN lesson.

In a vanilla RNN, information and gradients repeatedly pass through transformations involving the recurrent weight matrix and the derivative of tanh.

In an LSTM, the cell state has a more direct path:

ct=ft⊙ct−1+it⊙gtc_t=f_t\odot c_{t-1}+i_t\odot g_t

The old memory is multiplied by the forget gate and then added to the new information.

Along this direct path, the local derivative with respect to the previous cell state is ftf_t, holding the gate outputs fixed.

If the forget gate stays close to 1, information and gradients can be preserved across many time steps.

7. Let's build an LSTM cell from scratch

This is the code I particularly want you to understand.

It takes the same micrograd concepts you've learned and implements an LSTM cell without using nn.LSTM.

import torch
import torch.nn as nn

class MyLSTMCell(nn.Module):
    def __init__(self, input_size, hidden_size):
        super().__init__()

        self.hidden_size = hidden_size

        # 4 gate transformations together
        self.gates = nn.Linear(
            input_size + hidden_size,
            4 * hidden_size
        )

    def forward(self, x, h_prev, c_prev):

        # Combine current input and previous hidden state
        combined = torch.cat([x, h_prev], dim=1)

        # Four sets of gate values
        i, f, g, o = self.gates(combined).chunk(4, dim=1)

        # Activations
        i = torch.sigmoid(i)
        f = torch.sigmoid(f)
        g = torch.tanh(g)
        o = torch.sigmoid(o)

        # Update long-term memory
        c = f * c_prev + i * g

        # Produce new hidden state
        h = o * torch.tanh(c)

        return h, c

cell = MyLSTMCell(input_size=1, hidden_size=16)

x = torch.randn(32, 1)
h = torch.zeros(32, 16)
c = torch.zeros(32, 16)

h, c = cell(x, h, c)

print(h.shape)  # (32, 16)
print(c.shape)  # (32, 16)

Notice how little new mathematics we've introduced.

nn.Linear computes weighted sums, sigmoid produces gate values, tanh generates candidate information, and multiplication/addition update memory.

We combined four gate computations into one larger Linear layer for efficiency. This is mathematically equivalent to using four separate affine transformations. This educational cell has one bias vector per gate, unlike PyTorch's built-in LSTM, which stores two.

import torch.nn as nn

    def __init__(self):

            input_size=1,
            hidden_size=16,
            num_layers=1,
            batch_first=True

        self.classifier = nn.Linear(16, 1)

        # Final hidden state of the final layer
        h_last = h_n[-1]

        # One logit per sequence

            logits = model(X)
            val_loss += loss_fn(logits, y).item() * len(X)

10. What about the GRU?

Now that we understand LSTMs, GRUs are much easier.

GRU stands for Gated Recurrent Unit.

A GRU also uses learnable gates to control recurrence, but it has a simpler design.

LSTM

Forget gate

What to retain?

Input gate

What to write?

Output gate

What to expose?

Two states: c and h

GRU

Update gate

Keep old state or replace it?

Reset gate

How much past state matters for the candidate?

Candidate state

Proposed new information

One state: h

A GRU doesn't maintain a separate ctc_t. It updates its hidden state directly.

One common GRU update convention, including PyTorch's, is:

ht=zt⊙ht−1+(1−zt)⊙h~t\boxed{h_t=z_t\odot h_{t-1}+(1-z_t)\odot\tilde h_t}

Where ztz_t is the update gate and h~t\tilde h_t is the candidate hidden state.

If ztz_t is close to 1, much of the old hidden state is preserved.

If it's close to 0, the new candidate dominates.

The reset gate controls how much previous hidden-state information is used when constructing that candidate.

So a GRU preserves much of the memory-control intuition of an LSTM, but with fewer trainable transformations.

GRU implementation

class SequenceGRU(nn.Module):
    def __init__(self):
        super().__init__()

        self.gru = nn.GRU(
            input_size=1,
            hidden_size=16,

        )

        self.classifier = nn.Linear(16, 1)

    def forward(self, x):
        all_states, h_n = self.gru(x)

        h_last = h_n[-1]

        return self.classifier(h_last)

It's tempting to assume that LSTMs always outperform GRUs because they have more gates.

That's not true.

Both can work well, and their relative performance depends on the task, data and training conditions. GRUs can be more computationally economical because they use fewer parameters at a given hidden size.

12. Where does backpropagation happen?

This connects directly to your previous question about RNNs.

In our LSTM sequence classifier:

Mini-batch: (32, 30, 1)

Forward through time

At every step, update both hₜ and cₜ using the same learned weights.

Final h₃₀ → Linear → One logit per sequence

BCEWithLogitsLoss → Average batch loss

Backpropagation through time

Gradients flow backward through gates, hidden states and cell states across all 30 steps.

Gradient clipping → AdamW update

Next mini-batch of independent sequences

The central training loop has not changed.

In our classifier, we calculate one loss after processing each entire sequence. Backpropagation then traverses the unrolled computations and accumulates gradients for the shared parameters.

A different LSTM task could calculate a loss at every time step instead.

Final mental model — What did LSTM and GRU add?

1. The neuron operations are still familiar.

Linear transformations, sigmoid, tanh, multiplication and addition.

2. The LSTM carries two recurrent states.

The cell state preserves internal memory, while the hidden state exposes information used by subsequent computations.

3. Gates are small learned neural-network computations.

They control memory retention, writing and exposure using values between 0 and 1.

4. The GRU simplifies gated recurrence.

It uses a single hidden state and update/reset gates instead of a separate LSTM cell state.

5. Training is still backpropagation through time.

The same recurrent parameters are reused throughout the sequence, and the optimizer updates them after gradients are calculated.

We've now learned how recurrent networks maintain information over time.

But imagine translating a sentence with 50 words. If we use one final hidden state to represent the entire sentence, we're asking a fixed-size vector to carry all the information needed for translation.

That creates an information bottleneck.

Our next architecture will introduce encoder–decoder networks and attention, allowing a decoder to selectively access different parts of the input sequence instead of relying entirely on one final summary.

This will be our bridge from recurrent neural networks to Transformers.

1. First innovation — Encoder and decoder

Our previous RNN classifier was:

Sequence → RNN → Final hidden state → One classification output

Now we want multiple outputs.

We can use two recurrent neural networks:

  • Encoder: Reads the entire input and builds a representation.
  • Decoder: Uses that representation to generate the output sequence step by step.

Basic Seq2Seq without attention: the encoder's final hidden state summarizes the source for the decoder.

We can even reuse the GRU architecture from our previous lesson.

The encoder

It processes the input sequentially:

hi=GRU⁡(xi,hi−1)h_i=\operatorname{GRU}(x_i,h_{i-1})

For [2, 7, 4, 9], it computes:

h1, h2, h3, h4h_1,\ h_2,\ h_3,\ h_4

In the basic encoder–decoder model, the final encoder state h4h_4 is used to initialize the decoder's hidden state.

The decoder

The decoder generates one output at a time:

st=GRU⁡(yt−1,st−1)s_t=\operatorname{GRU}(y_{t-1},s_{t-1})

Here yt−1y_{t-1} is the previous output token, represented by a learned embedding. The initial decoder input is a special beginning-of-sequence token.

A classifier then converts the decoder hidden state into vocabulary logits.

Important: The encoder and decoder are two separate recurrent networks, each with its own learned parameters.

But both are still built using the same neural-network operations we already understand.

2. The problem — One fixed-size representation

Imagine translating a sentence containing 50 words.

A basic Seq2Seq model can be forced to summarize the source into one fixed-size vector before decoding.

50 source tokens

Encoder GRU

One fixed-size context vector

For example, 32 hidden values

Decoder generates the output sequence

The decoder must rely on information compressed into that representation.

It can be difficult to preserve all the information needed for long or complex inputs.

This is known as the fixed-context bottleneck.

We need a mechanism that allows the decoder to consult different parts of the original input sequence while generating its output.

That's where attention comes in.

3. The second innovation — Attention

Instead of discarding the intermediate encoder hidden states, we keep all of them:

H=[h1,h2,h3,h4]H=[h_1,h_2,h_3,h_4]

At every decoder step, the decoder can calculate how relevant each encoder hidden state is to the next output.

Conceptual illustration: when generating the first reversed element, the decoder may focus strongly on the final source position.

Notice the change:

  • Without attention: The decoder depends on the encoded source through one initial summary.
  • With attention: The decoder can calculate a new weighted combination of all encoder outputs at every generation step.

We haven't removed the RNN.

We've introduced an extra computation between the encoder's hidden states and the decoder.

4. Exactly how does attention work?

Attention involves three operations.

Step A — Calculate relevance scores

The decoder has a previous hidden state st−1s_{t-1}, representing its current decoding context.

It compares that state with each encoder hidden state hih_i.

A commonly used additive-attention formula is:

et,i=vTtanh⁡(Wsst−1+Whhi)e_{t,i}=v^T\tanh(W_s s_{t-1}+W_hh_i)

This should look familiar!

Inside the attention scorer, we have:

  • Weighted sums.
  • A tanh activation.
  • Another learned projection to a scalar.

The attention scorer is itself a small neural network.

It produces one relevance score for each source position.

Step B — Convert scores into attention weights

We apply softmax across the source positions:

αt,i=exp⁡(et,i)∑jexp⁡(et,j)\alpha_{t,i}= \frac{\exp(e_{t,i})} {\sum_j\exp(e_{t,j})}

The weights are nonnegative and add up to 1.

Step C — Calculate the context vector

We compute a weighted sum of encoder hidden states:

ct=∑iαt,ihi\boxed{c_t=\sum_i\alpha_{t,i}h_i}

This is the context vector for decoder step tt.

A different decoder step can produce different attention scores, weights and context.

That last point is fundamental: the attention context is dynamic, not fixed for the entire output sequence.

Let's simulate attention across four decoder steps.

For clarity, we'll manually assign higher relevance to the correct source position at each step. A trained model would calculate these scores using its learned attention network.

Notice what happened.

At step 1, the decoder focuses on the representation associated with input 9.

At step 2, it focuses on input 4.

The decoder can learn to change its attention distribution depending on what it is currently trying to generate.

What should you remember?

Attention is a learned, input-dependent weighted averaging mechanism.

The encoder supplies the representations. The decoder supplies the current query. The attention scorer determines how to combine those representations.

And importantly, attention weights themselves are calculated activations, not separately initialized trainable parameters. The weights inside the attention scorer are trainable.

6. Connecting attention to the decoder

Now we need to connect all three pieces:

Encoder → Attention → Decoder

At each output step tt:

  1. The decoder's previous hidden state is compared with all encoder hidden states.
  2. Attention produces a context vector ctc_t.
  3. The decoder receives that context and the previous output token.
  4. Its recurrent cell updates its hidden state.
  5. A final Linear layer produces logits for the next token.

We can express that as:

st=GRU⁡([Emb⁡(yt−1);ct],st−1)s_t=\operatorname{GRU}([\operatorname{Emb}(y_{t-1});c_t],s_{t-1})
logits⁡t=Wo[st;ct]+bo\operatorname{logits}_t=W_o[s_t;c_t]+b_o

The brackets with a semicolon mean concatenation of feature vectors.

Notice we're still using a familiar GRU and a familiar Linear layer.

A new small component: Embeddings

Our inputs are now discrete symbols rather than continuous measurements.

The number 9, for example, represents a token category. We don't necessarily want its numerical magnitude to determine its meaning.

A learned embedding table maps each token ID to a vector:

9⟶Emb⁡(9)∈R169\longrightarrow \operatorname{Emb}(9)\in\mathbb R^{16}

The embedding table is a matrix of trainable parameters. We'll explore embeddings more deeply in our Transformer lessons.

During training, we already know the correct target sequence.

We can feed the correct previous token to the decoder at each step.

This is called teacher forcing.

9. Where does the loss happen?

This is a major distinction from our previous RNN and LSTM classification case studies.

Previously, we used the final hidden state to produce one prediction per entire sequence.

Now our decoder produces one prediction at every output step.

For our example, the decoder should predict:

9 → 4 → 7 → 2 → EOS

Each step produces 13 logits, because our vocabulary contains 13 tokens.

We calculate Cross-Entropy for each correct next token and average across valid target positions in the batch:

L=1Nvalid∑valid output positions−log⁡P(yt∣y<t,X)\boxed{ L=\frac{1}{N_{\text{valid}}} \sum_{\text{valid output positions}} -\log P(y_t\mid y_{<t},X) }

11. PyTorch — Build the complete attention model

This is the central code of our case study. We'll implement additive attention, the classic form associated with early attention-based encoder–decoder RNNs.

First, the model:

import torch
import torch.nn as nn
import torch.nn.functional as F

from torch.nn.utils.rnn import (
    pack_padded_sequence,
    pad_packed_sequence
)

# Digit IDs: 0-9
BOS, EOS, PAD = 10, 11, 12
VOCAB = 13

EMBED = 16
HIDDEN = 32

class Seq2SeqAttention(nn.Module):
    def __init__(self):
        super().__init__()

        # Learned token representations
        self.src_embedding = nn.Embedding(
            VOCAB, EMBED, padding_idx=PAD
        )
        self.tgt_embedding = nn.Embedding(
            VOCAB, EMBED, padding_idx=PAD
        )

        # Encoder: familiar GRU
        self.encoder = nn.GRU(
            EMBED, HIDDEN, batch_first=True
        )

        # Additive attention scorer
        self.key = nn.Linear(HIDDEN, HIDDEN, bias=False)
        self.query = nn.Linear(HIDDEN, HIDDEN, bias=False)
        self.score = nn.Linear(HIDDEN, 1, bias=False)

        # Decoder: one recurrent step at a time
        self.decoder = nn.GRUCell(
            EMBED + HIDDEN, HIDDEN
        )

        # Next-token classifier
        self.head = nn.Linear(
            2 * HIDDEN, VOCAB
        )

    def encode(self, src, lengths):
        x = self.src_embedding(src)

        # Avoid processing padding as real sequence data
        packed = pack_padded_sequence(
            x,
            lengths.cpu(),
            batch_first=True,
            enforce_sorted=False
        )

        packed_out, h = self.encoder(packed)

        enc_out, _ = pad_packed_sequence(
            packed_out,
            batch_first=True,
            total_length=src.size(1)
        )

        # True = valid source position
        mask = src != PAD

        return enc_out, h[-1], mask

    def decode_step(self, prev_token, hidden,
                    enc_out, mask):

        # 1. Attention scores
        energy = torch.tanh(
            self.key(enc_out)
            + self.query(hidden).unsqueeze(1)
        )

        scores = self.score(energy).squeeze(-1)

        # Ignore padded source positions
        scores = scores.masked_fill(~mask, -1e9)

        # 2. Attention weights
        weights = torch.softmax(scores, dim=1)

        # 3. Weighted context vector
        context = (
            weights.unsqueeze(-1) * enc_out
        ).sum(dim=1)

        # 4. Decoder update
        token_emb = self.tgt_embedding(prev_token)

        decoder_input = torch.cat(
            [token_emb, context], dim=1
        )

        new_hidden = self.decoder(
            decoder_input, hidden
        )

        # 5. Predict next token
        logits = self.head(
            torch.cat([new_hidden, context], dim=1)
        )

        return logits, new_hidden, weights

    def forward(self, src, lengths, tgt):
        enc_out, h, mask = self.encode(src, lengths)

        logits_list = []
        attention_list = []

        # Teacher forcing
        for t in range(tgt.size(1) - 1):
            logits, h, weights = self.decode_step(
                tgt[:, t], h, enc_out, mask
            )

            logits_list.append(logits)
            attention_list.append(weights)

        return (
            torch.stack(logits_list, dim=1),
            torch.stack(attention_list, dim=1)
        )

    @torch.no_grad()
    def generate(self, src, lengths, max_steps=8):
        enc_out, h, mask = self.encode(src, lengths)

        prev = torch.full(
            (src.size(0),), BOS,
            dtype=torch.long, device=src.device
        )

        outputs = []
        attention_list = []

        for _ in range(max_steps):
            logits, h, weights = self.decode_step(
                prev, h, enc_out, mask
            )

            prev = logits.argmax(dim=-1)

            outputs.append(prev)
            attention_list.append(weights)

        return (
            torch.stack(outputs, dim=1),
            torch.stack(attention_list, dim=1)
        )

model = Seq2SeqAttention()

print(sum(p.numel() for p in model.parameters()))

Notice that the attention weights produced for individual examples and steps aren't themselves trainable parameters. They're calculated from the current hidden representations by the attention scorer.

13. Training: Same loop, more interesting forward pass

The training loop should now look extremely familiar.

optimizer = torch.optim.AdamW(
    model.parameters(), lr=0.003
)

history = {"train": [], "val": []}

for epoch in range(15):
    model.train()
    train_total = 0.0

    for src, lengths, tgt in train_loader:
        optimizer.zero_grad()

        logits, attention = model(
            src, lengths, tgt
        )

        # Predict the target AFTER BOS
        targets = tgt[:, 1:]

        loss = F.cross_entropy(
            logits.reshape(-1, VOCAB),
            targets.reshape(-1),
            ignore_index=PAD
        )

        loss.backward()

        torch.nn.utils.clip_grad_norm_(
            model.parameters(), max_norm=1.0
        )

        optimizer.step()

        train_total += loss.item()

    model.eval()
    val_total = 0.0

    with torch.no_grad():
        for src, lengths, tgt in val_loader:
            logits, _ = model(src, lengths, tgt)

            loss = F.cross_entropy(
                logits.reshape(-1, VOCAB),
                tgt[:, 1:].reshape(-1),
                ignore_index=PAD
            )

            val_total += loss.item()

    train_loss = train_total / len(train_loader)
    val_loss = val_total / len(val_loader)

    history["train"].append(train_loss)
    history["val"].append(val_loss)

    print(
        f"Epoch {epoch+1}: "
        f"train={train_loss:.3f}, "
        f"val={val_loss:.3f}"
    )

The reported values are averages of mini-batch losses. Because batches can contain different numbers of valid target tokens, these are not exactly the same as a single token-weighted mean over the whole dataset.

Also, this validation loss uses teacher forcing. It's useful for monitoring learning, but it's not the same as measuring how accurately the model generates complete sequences on its own.

Let's test that separately.

16. How does backpropagation work through attention?

This is the final important conceptual connection.

In our previous RNN lessons, gradients flowed backward through time.

Now gradients also flow through the attention computations.

Output-token Cross-Entropy losses → Decoder logits and hidden states → Attention context and weights → Weighted sum, softmax and scoring network → All encoder hidden states → Encoder recurrence and embeddings.

Gradients accumulate for shared trainable parameters. In reality, this computational graph has multiple branches and paths. Gradients from all relevant paths accumulate according to the chain rule.

The significant new feature is that an output loss can directly influence the encoder representations it attended to, rather than depending exclusively on information transmitted through the encoder's final hidden state.

That can provide shorter paths for information and gradients between the decoder and different source positions.

But the underlying backpropagation algorithm remains unchanged.

18. The complete architecture in our universal training loop

One-time setup — Initialize embeddings, encoder, decoder, attention scorer, classifier and optimizer.

Mini-batch of source sequences + targets. Token embeddings → Encoder GRU → All encoder states. Attention scores → Softmax → Context. Decoder GRU → Next-token logits. Repeat attention and decoding at each output step.

Cross-Entropy over valid output tokens → Scalar loss. Backpropagation through decoder, attention and encoder. Gradient clipping → AdamW update. Next mini-batch · Validate periodically · Repeat.

  • It can calculate a different distribution over the 20 encoder positions at each decoder step.
  • It replaces backpropagation and learns without gradients.
  • It creates 20 new trainable weight matrices for every output step.

Answer. It can calculate a different distribution over the 20 encoder positions at each decoder step.

Final mental model — What did Seq2Seq and attention introduce?

  1. Encoder–decoder separates reading from generating. The encoder processes the source sequence. The decoder produces the output sequence step by step.
  2. Basic Seq2Seq has a fixed-context bottleneck. The decoder may have to rely on information compressed into the encoder's final state.
  3. Attention dynamically selects relevant source information. A learned scoring network produces relevance scores, softmax normalizes them, and a weighted sum creates a context vector.
  4. Generation is autoregressive. The decoder produces one token at a time, conditioned on earlier tokens and the encoded input.
  5. Training is still ordinary gradient-based learning. Token-level cross-entropy produces a scalar loss, and backpropagation reaches the encoder, attention and decoder parameters.

  • Seq2Seq + Attention: Let a decoder dynamically retrieve information from encoder states.

1. What fundamentally changes from an RNN?

Remember our RNN:

ht=tanh⁡(Wxxt+Whht−1+b)h_t=\tanh(W_xx_t+W_hh_{t-1}+b)

Each state depends on the preceding state.

RNN — Information moves through time

To influence later positions, information passes through a chain of recurrent computations.

Transformer self-attention — Direct token interaction

Each output token representation can combine information from all input positions in the same self-attention layer.

The key change: Rather than passing information through a sequence of recurrent states, self-attention allows each position to read information from other positions directly.

For an encoder, this interaction is normally bidirectional: a token can attend to earlier and later tokens.

There's still a sequence dimension, but no hidden state needs to be carried sequentially from step 1 to step 2 to step 3.

Within a layer, token interactions can be calculated in parallel.

3. Self-attention — The three matrices Q, K and V

Now we reach the most important part.

In our previous attention lesson, the decoder compared its current hidden state against encoder hidden states.

In a Transformer encoder, all Queries, Keys and Values come from the same input sequence.

Every token produces three learned representations:

  • Query (Q): What information am I looking for?
  • Key (K): What information can this position match against?
  • Value (V): What information will this position contribute if attended to?

These are intuitive descriptions. Mathematically, they're just linear projections.

Q=XWQ,K=XWK,V=XWV\boxed{ Q=XW_Q,\quad K=XW_K,\quad V=XW_V }

Biases may also be included.

Input token vectors X

Compare Q with K → Attention scores

Softmax → Attention weights

Weighted combination of V → Contextual token vectors

Important: Q, K and V aren't three separate types of neurons. They're three learned linear transformations applied to the input representations.

This is our original Wx + b operation again.

4. Scaled dot-product attention — The actual calculation

Instead of using the additive attention scorer from our previous lesson, the Transformer uses dot products.

The full equation is:

Attention⁡(Q,K,V)=softmax⁡(QKTdk)V\boxed{\operatorname{Attention}(Q,K,V)=\operatorname{softmax}\left(\frac{QK^T}{\sqrt{d_k}}\right)V}

It looks complicated, but it contains only three familiar operations:

Matrix multiplication → Softmax → Matrix multiplication.

Let's calculate one example manually.

One query attending to two tokens

Suppose our query is:

q=[1,0]q=[1,0]

And we have two keys:

k1=[1,0],k2=[0,1]k_1=[1,0],\qquad k_2=[0,1]

The query–key dot products are:

q⋅k1=1,q⋅k2=0q\cdot k_1=1,\qquad q\cdot k_2=0

Since the key dimension is 2, we divide by 2\sqrt2:

scores=[0.707,0]\text{scores}=[0.707,0]

Applying softmax gives approximately:

α=[0.670,0.330]\boxed{\alpha=[0.670,0.330]}

So the query gives about 67% weight to the first token and 33% to the second.

Now suppose their Value vectors are:

v1=[2,0],v2=[0,4]v_1=[2,0],\qquad v_2=[0,4]

The attention output is:

z=0.670[2,0]+0.330[0,4]z=0.670[2,0]+0.330[0,4]
z≈[1.340,1.320]\boxed{z\approx[1.340,1.320]}

Notice what happened.

We didn't select one token exclusively. We created a weighted combination of information from both tokens.

We vary only the first score while keeping the second score at zero. In a real model, the scores come from learned Q/K projections and current token representations.

Why divide by dk\sqrt{d_k}?

Because dot products tend to grow in magnitude as the key/query dimension increases, under common assumptions about their component scales. Large scores can cause softmax to become extremely peaked, resulting in small gradients.

Scaling helps control that effect.

5. Self-attention computes a matrix of relationships

So far, we calculated attention for one query.

But in a Transformer encoder, every token has its own query.

Suppose we have four tokens:

[CLS, A, x, B]

Each query compares itself against all four keys.

So we calculate a matrix of attention scores:

QKT∈R4×4QK^T\in\mathbb R^{4\times4}

The attention weights also form a 4 × 4 matrix.

The output of the attention operation contains a new contextual representation for every token, not just one summary vector.

With a single head:

Z=AVZ=AV

Where AA is the attention-weight matrix.

For a batch, the attention matrix has shape:

(B,T,T)\boxed{(B,T,T)}

This is fundamentally different from the RNN's recurrent chain. Every position can incorporate information from other positions in the same layer.

And there's no autoregressive causal mask here: an encoder token can attend to both earlier and later tokens.

We'll introduce causal masking when we build a GPT-style decoder.

6. Multi-head attention — Several attention mechanisms in parallel

Why use just one attention mechanism?

Different learned projections can capture different relationships.

For example, one head might learn to emphasize adjacent tokens, while another may focus on distant dependencies.

This isn't guaranteed, but multiple heads provide the model with different representational subspaces.

10. PyTorch — Implement self-attention from scratch

Let's code the most important new operation ourselves rather than hide it inside a framework module.

import math
import torch
import torch.nn as nn
import torch.nn.functional as F

class SelfAttention(nn.Module):
    def __init__(self, dim=32, heads=4):
        super().__init__()

        assert dim % heads == 0

        self.heads = heads
        self.d = dim // heads

        # Three learned projections: Q, K and V
        self.qkv = nn.Linear(dim, 3 * dim)

        # Combine attention heads
        self.proj = nn.Linear(dim, dim)

    def forward(self, x, mask):
        B, T, D = x.shape

        # (B, T, 3, heads, head_dim)
        qkv = self.qkv(x).reshape(
            B, T, 3, self.heads, self.d
        )

        # (3, B, heads, T, head_dim)
        qkv = qkv.permute(2, 0, 3, 1, 4)

        q, k, v = qkv.unbind(0)

        # Compare every query with every key
        # (B, heads, T, T)
        scores = q @ k.transpose(-2, -1)
        scores = scores / math.sqrt(self.d)

        # Disallow attention TO padded positions
        scores = scores.masked_fill(
            ~mask[:, None, None, :],
            torch.finfo(scores.dtype).min
        )

        # Attention probabilities
        weights = torch.softmax(scores, dim=-1)

        # Weighted values
        out = weights @ v

        # Combine heads: (B, T, D)
        out = out.transpose(1, 2).reshape(B, T, D)

        return self.proj(out), weights

attention = SelfAttention()

x = torch.randn(2, 5, 32)
mask = torch.ones(2, 5, dtype=torch.bool)

output, weights = attention(x, mask)

print(output.shape)   # (2, 5, 32)
print(weights.shape)  # (2, 4, 5, 5)

This is the heart of the Transformer.

The code follows exactly the sequence we visualized:

X→Q,K,V→QKT→Softmax→AV\boxed{X\rightarrow Q,K,V\rightarrow QK^T\rightarrow\text{Softmax}\rightarrow AV}

The mask prevents valid tokens from attending to padding. It doesn't prevent attention to future tokens, because this is a bidirectional encoder.

In production, PyTorch offers optimized attention operations, including nn.MultiheadAttention and scaled-dot-product attention. Our explicit implementation is better for learning the underlying operations.

11. Implement the encoder block and full model

Now assemble what we've already learned.

class EncoderBlock(nn.Module):
    def __init__(self):
        super().__init__()

        self.norm1 = nn.LayerNorm(32)
        self.attn = SelfAttention(dim=32, heads=4)

        self.norm2 = nn.LayerNorm(32)

        self.ffn = nn.Sequential(
            nn.Linear(32, 64),
            nn.GELU(),
            nn.Linear(64, 32)
        )

    def forward(self, x, mask):
        # Self-attention + residual
        updated, weights = self.attn(
            self.norm1(x), mask
        )

        x = x + updated

        # MLP + residual
        x = x + self.ffn(self.norm2(x))

        return x, weights

class TinyTransformerEncoder(nn.Module):
    def __init__(self):
        super().__init__()

        self.token_embedding = nn.Embedding(
            8, 32, padding_idx=0
        )

        self.position_embedding = nn.Embedding(
            9, 32
        )

        self.blocks = nn.ModuleList([
            EncoderBlock(),
            EncoderBlock()
        ])

        self.final_norm = nn.LayerNorm(32)
        self.classifier = nn.Linear(32, 2)

    def forward(self, token_ids):
        B, T = token_ids.shape

        # Valid positions, excluding padding
        mask = token_ids != 0

        positions = torch.arange(
            T, device=token_ids.device
        )

        # Token identity + token position
        x = (
            self.token_embedding(token_ids)
            + self.position_embedding(positions)[None, :, :]
        )

        attention_maps = []

        for block in self.blocks:
            x, weights = block(x, mask)
            attention_maps.append(weights)

        # Classify using the [CLS] representation
        cls_vector = self.final_norm(x[:, 0])

        logits = self.classifier(cls_vector)

        return logits, attention_maps

13. Train the Transformer

Now comes the satisfying part.

Our training loop is exactly the one we've used since micrograd.

model = TinyTransformerEncoder()

optimizer = torch.optim.AdamW(
    model.parameters(),
    lr=0.002,
    weight_decay=0.01
)

loss_fn = nn.CrossEntropyLoss()

history = {"train": [], "val": [], "accuracy": []}

for epoch in range(15):
    model.train()

    train_total = 0.0

    for xb, yb in train_loader:
        optimizer.zero_grad()

        # Forward
        logits, attention_maps = model(xb)

        # Loss
        loss = loss_fn(logits, yb)

        # Backward
        loss.backward()

        # Clip large gradients
        torch.nn.utils.clip_grad_norm_(
            model.parameters(), max_norm=1.0
        )

        # Update weights
        optimizer.step()

        train_total += loss.item() * len(xb)

    train_loss = train_total / len(train_data)

    # Validation
    model.eval()

    val_total = 0.0
    correct = 0

    with torch.no_grad():
        for xb, yb in val_loader:
            logits, _ = model(xb)

            val_total += (
                loss_fn(logits, yb).item() * len(xb)
            )

            correct += (
                logits.argmax(dim=-1) == yb
            ).sum().item()

    val_loss = val_total / len(val_data)
    accuracy = correct / len(val_data)

    history["train"].append(train_loss)
    history["val"].append(val_loss)
    history["accuracy"].append(accuracy)

    print(
        f"Epoch {epoch+1}: "
        f"train={train_loss:.3f}, "
        f"val={val_loss:.3f}, "
        f"accuracy={accuracy:.1%}"
    )

15. Where does backpropagation happen?

Exactly where you'd expect.

Input token IDs + positional IDs → Transformer Encoder × 2

Q/K/V projections → Attention → Residual → FFN → Residual

Final [CLS] vector → 2 logits → Cross-Entropy → Average batch loss

Backward through classifier, residuals, MLPs, normalization, softmax, attention and embeddings

Gradient clipping → AdamW → Update parameters → Next mini-batch

The interesting difference from RNNs is that we're no longer backpropagating through a recurrent chain of time steps.

Instead, gradients flow through the matrix operations, attention connections, residual paths and stacked Transformer blocks.

It's still ordinary reverse-mode automatic differentiation and the chain rule.

Also, the attention-weight matrices aren't updated directly by AdamW. The optimizer updates Q/K/V projection weights, embeddings and other trainable parameters that produce the attention weights.

That becomes important when processing very long documents.

17. How does this relate to BERT?

Our model is a small, randomly initialized Transformer encoder trained directly on a supervised classification task.

BERT uses a Transformer encoder architecture too, but with a much more substantial training process.

  • Transformer encoder is an architectural building block.
  • BERT is a particular family of pretrained, bidirectional Transformer encoder models.

BERT-style pretraining typically involves masked language modeling: some tokens are masked or corrupted, and the model learns to recover their original identities using surrounding context.

Our case study instead directly optimizes a binary classification objective.

So we're learning the architectural foundation, not recreating BERT's pretraining pipeline.

Final mental model — What did the Transformer Encoder introduce?

  1. Tokens become learned vectors with positional information. We represent both token identity and position.
  2. Q, K and V are ordinary learned linear projections. Attention scores come from query–key dot products, followed by scaling and softmax.
  3. Self-attention mixes information between tokens. Every token can acquire context from other tokens in the same sequence.
  4. Multi-head attention learns multiple interaction patterns. Different heads operate on different learned projections of the token representations.
  5. The Transformer block still contains an MLP. Attention mixes information between positions; the feed-forward network transforms each token's features.
  6. Residual connections and LayerNorm stabilize deep stacks. These are exactly the mechanisms from our foundational lessons.
  7. The training loop remains unchanged. Forward → Loss → Backward → Optimizer → Repeat.

Next architecture — Transformer Decoder (GPT-style)

We've now built a network where every token can access both earlier and later tokens.

But there's a problem if our goal is text generation.

Suppose we want to predict the next word in:

During training, if a token can attend to future tokens, it could see information that wouldn't exist yet during actual generation.

2. Causal masking — The essential new operation

Recall our original self-attention equation:

Attention⁡(Q,K,V)=softmax⁡(QKTdk)V\operatorname{Attention}(Q,K,V) =\operatorname{softmax}\left(\frac{QK^T}{\sqrt{d_k}}\right)V

In a decoder-only Transformer, we add a causal mask before softmax:

A=softmax⁡(QKTdk+M)\boxed{ A=\operatorname{softmax} \left(\frac{QK^T}{\sqrt{d_k}}+M\right) }

Where:

Mij={0j≤i−∞j>iM_{ij}= \begin{cases} 0 & j\leq i\\ -\infty & j>i \end{cases}

The −∞-\infty values make future-position probabilities zero after softmax.

An essential subtlety

A causal mask doesn't mean the network processes tokens sequentially during training.

It means each position's representation is mathematically prevented from depending on future tokens.

The entire attention matrix can still be computed in parallel.

That distinction will become especially important when we compare training and generation.

An important connection to teacher forcing

Remember our Seq2Seq lesson?

7. Sampling — How does a model choose its next token?

The final Linear layer produces logits, just as in our classification lessons.

Suppose the next-character logits are:

Character Logit
a 3.0
b 1.5
c 0.5

Softmax converts these into probabilities.

We could always choose the highest-probability token. That's called greedy decoding.

But generation can also sample from the probability distribution.

One important control is temperature:

P(xi)=exp⁡(zi/τ)∑j=1Vexp⁡(zj/τ)\boxed{ P(x_i)=\frac{\exp(z_i/\tau)}{\sum_{j=1}^{V}\exp(z_j/\tau)} }

Where τ>0\tau>0.

  • Lower temperature produces a more concentrated distribution.
  • Higher temperature produces a flatter distribution.
  • Temperature doesn't change the learned weights.

Temperature controls sampling behavior during generation, not the underlying next-token training objective.

Other generation techniques include top-k, top-p (nucleus) sampling and repetition penalties. We'll keep our first implementation simple.

9. PyTorch — Build causal self-attention ourselves

Let's implement the essential new mechanism directly.

We'll use ordinary matrix operations rather than hiding them behind nn.Transformer.

import math
import torch
import torch.nn as nn
import torch.nn.functional as F

# Our miniature language-model dimensions
BLOCK_SIZE = 32
D_MODEL = 32
HEADS = 4
FF_DIM = 64
DROPOUT = 0.1

class CausalSelfAttention(nn.Module):
    def __init__(self):
        super().__init__()

        self.head_dim = D_MODEL // HEADS

        # One projection generates Q, K and V
        self.qkv = nn.Linear(D_MODEL, 3 * D_MODEL)

        # Output projection after combining heads
        self.proj = nn.Linear(D_MODEL, D_MODEL)
        self.dropout = nn.Dropout(DROPOUT)

        # Lower-triangular causal mask
        mask = torch.tril(torch.ones(
            BLOCK_SIZE, BLOCK_SIZE, dtype=torch.bool
        ))

        self.register_buffer("causal_mask", mask)

    def forward(self, x):
        B, T, D = x.shape

        # (B, T, 3D) -> three (B, T, D) tensors
        q, k, v = self.qkv(x).chunk(3, dim=-1)

        # Split each into attention heads
        def split_heads(t):
            return t.reshape(
                B, T, HEADS, self.head_dim
            ).transpose(1, 2)

        q = split_heads(q)
        k = split_heads(k)
        v = split_heads(v)

        # (B, HEADS, T, T)
        scores = q @ k.transpose(-2, -1)
        scores = scores / math.sqrt(self.head_dim)

        # The KEY difference from encoder attention
        scores = scores.masked_fill(
            ~self.causal_mask[:T, :T],
            float("-inf")
        )

        # Future positions now get zero probability
        weights = torch.softmax(scores, dim=-1)

        # Weighted values
        out = weights @ v

        # Recombine heads: (B, T, D)
        out = out.transpose(1, 2).reshape(B, T, D)

        return self.dropout(self.proj(out)), weights

Compare this with the self-attention code from our previous lesson.

Almost everything is identical.

The critical addition is:

scores = scores.masked_fill(
    ~self.causal_mask[:T, :T],
    float("-inf")
)

That one operation changes the information-flow rules of the architecture.

PyTorch also provides optimized causal attention through F.scaled_dot_product_attention(q, k, v, is_causal=True). We're keeping the calculation explicit so you can see exactly what happens.

10. Build the Transformer blocks and language model

We'll stack two blocks with the familiar pre-normalization, residual connections and feed-forward MLP.

class GPTBlock(nn.Module):
    def __init__(self):
        super().__init__()

        self.ln1 = nn.LayerNorm(D_MODEL)
        self.attn = CausalSelfAttention()

        self.ln2 = nn.LayerNorm(D_MODEL)

        self.mlp = nn.Sequential(
            nn.Linear(D_MODEL, FF_DIM),
            nn.GELU(),
            nn.Linear(FF_DIM, D_MODEL),
            nn.Dropout(DROPOUT)
        )

    def forward(self, x):
        # Causal self-attention + residual
        attn_output, weights = self.attn(self.ln1(x))
        x = x + attn_output

        # Ordinary MLP + residual
        x = x + self.mlp(self.ln2(x))

        return x, weights

class TinyGPT(nn.Module):
    def __init__(self, vocab_size):
        super().__init__()

        self.token_emb = nn.Embedding(
            vocab_size, D_MODEL
        )

        self.position_emb = nn.Embedding(
            BLOCK_SIZE, D_MODEL
        )

        self.blocks = nn.ModuleList([
            GPTBlock(),
            GPTBlock()
        ])

        self.ln_final = nn.LayerNorm(D_MODEL)

        # Predict one logit for each vocabulary token
        self.lm_head = nn.Linear(D_MODEL, vocab_size)

    def forward(self, token_ids):
        B, T = token_ids.shape

        assert T <= BLOCK_SIZE

        positions = torch.arange(
            T, device=token_ids.device
        )

        # Token identity + position
        x = (
            self.token_emb(token_ids)
            + self.position_emb(positions)[None, :, :]
        )

        attention_maps = []

        for block in self.blocks:
            x, weights = block(x)
            attention_maps.append(weights)

        x = self.ln_final(x)

        # (B, T, vocab_size)
        logits = self.lm_head(x)

        return logits, attention_maps

Notice what's absent:

There's no LSTM, no GRU, no recurrent hidden state, and no separate encoder.

And unlike our previous Transformer classifier, we don't extract a [CLS] vector.

We classify every position into a next-token vocabulary distribution.

13. The exciting part — Generate new text

Now we switch from training to generation.

The model receives an initial prompt, predicts one next token, appends it, and repeats.

@torch.no_grad()
def generate(
    model,
    prompt,
    max_new_tokens=100,
    temperature=0.8,
    top_k=None
):
    assert temperature > 0

    model.eval()

    ids = torch.tensor(
        [[stoi[ch] for ch in prompt]],
        dtype=torch.long,
        device=device
    )

    for _ in range(max_new_tokens):

        # Keep only the most recent context window
        context = ids[:, -BLOCK_SIZE:]

        # Forward pass
        logits, _ = model(context)

        # Only the LAST position predicts the next token
        next_logits = logits[:, -1, :] / temperature

        # Optional top-k filtering
        if top_k is not None:
            k = min(top_k, V)

            threshold = torch.topk(
                next_logits, k, dim=-1
            ).values[:, -1:]

            next_logits = next_logits.masked_fill(
                next_logits < threshold,
                float("-inf")
            )

        probs = F.softmax(next_logits, dim=-1)

        # Sample one token
        next_id = torch.multinomial(
            probs, num_samples=1
        )

        # Append it to the generated sequence
        ids = torch.cat([ids, next_id], dim=1)

    return decode(ids[0].tolist())


print(generate(
    model,
    prompt="the ",
    max_new_tokens=120,
    temperature=0.8
))

One important limitation of this implementation

Our model has a maximum context window of 32 characters.

After generating more than 32 characters, we drop older characters and reuse positional indices for the remaining window.

That's a simple sliding-window approach suitable for a toy model; real long-context language models use more sophisticated positional and inference mechanisms.

15. Why is generating text slower than training it?

Here's a subtle but important practical issue.

During training, we can process an entire sequence in parallel because the target tokens are already known and causal masking prevents information leakage.

During generation, the next token doesn't exist until we've produced it.

So decoding must proceed sequentially:

x1→x2→x3→⋯x_1\rightarrow x_2\rightarrow x_3\rightarrow\cdots

Our simple generation code recomputes attention over the available prefix at every step.

Real decoder-only models commonly improve this using a KV cache.

What is a KV cache?

Recall that every attention layer constructs:

Q=XWQ,K=XWK,V=XWVQ=XW_Q,\qquad K=XW_K,\qquad V=XW_V

When generating a new token, the representations for previous tokens may already have been calculated.

Instead of recomputing all previous Key and Value projections, we can cache them.

Without KV caching. Reprocess available prefix → Calculate attention → New token. Much of the previous computation is repeated.

With KV caching. Store previous Keys and Values separately for each attention layer. New token → Calculate its Query, Key and Value → Attend to cached Keys and Values plus the new token.

A KV cache:

  • Reduces redundant computation during autoregressive inference.
  • Uses additional memory to store past K/V representations.
  • Does not introduce new trainable parameters.

We'll explore its practical importance further when we move from tiny GPT models to modern LLM inference.

16. Where does backpropagation fit?

Our universal training loop remains intact.

One-time setup. Initialize embeddings, Transformer blocks, LM head, optimizer.

Mini-batch of input and shifted-target sequences. Token and positional embeddings → Causal multi-head attention → Residuals + LayerNorm + MLP × blocks → Final Linear → (B, T, V) logits.

Next-token Cross-Entropy. Average supervised positions → One scalar loss.

Backpropagation. Gradients through output head, MLPs, residuals, attention, normalization, Q/K/V projections and embeddings.

Clip gradients → AdamW updates shared parameters → Next mini-batch.

The causal mask itself has no trainable parameters.

Backpropagation only flows through allowed attention connections, and the shared Q/K/V projection matrices accumulate gradient contributions from all their uses.

During ordinary inference, we turn off gradient recording and don't update weights.

Final mental model — What makes GPT-style models different?

  1. The neural-network core is unchanged. Q/K/V projections, MLP layers, activations, normalization and residual connections remain familiar differentiable operations.
  2. Causal attention prevents looking into the future. Each position can attend only to itself and previous positions.
  3. Training predicts all next tokens in parallel. Shifted input/target sequences produce token-level Cross-Entropy losses averaged into one scalar.

  5. Temperature and sampling control selection, not learning. They transform or sample from the model's output probabilities during generation.

PyTorch snapshot

PyTorch's nn.Transformer combines encoder and decoder stacks.

import torch
import torch.nn as nn

D = 64
V = 20

embedding = nn.Embedding(V, D)
positions = nn.Embedding(32, D)

transformer = nn.Transformer(
    d_model=D,
    nhead=4,
    num_encoder_layers=2,
    num_decoder_layers=2,
    batch_first=True
)

head = nn.Linear(D, V)

# Example source and teacher-forced target
src = torch.tensor([[2, 7, 4, 9]])
target = torch.tensor([[10, 9, 4, 7, 2, 11]])

tgt_in = target[:, :-1]
tgt_expected = target[:, 1:]

def embed(ids):
    pos = torch.arange(ids.size(1))
    return embedding(ids) + positions(pos)[None]

T = tgt_in.size(1)

# True = blocked future position
causal_mask = torch.triu(
    torch.ones(T, T, dtype=torch.bool),
    diagonal=1
)

hidden = transformer(
    src=embed(src),
    tgt=embed(tgt_in),
    tgt_mask=causal_mask
)

logits = head(hidden)

loss = nn.CrossEntropyLoss()(
    logits.reshape(-1, V),
    tgt_expected.reshape(-1)
)

print(logits.shape)  # (1, 5, 20)
print(loss.shape)    # scalar

This demonstrates one forward and loss calculation. With an optimizer and loss.backward(), we'd have the same training loop as before.

During training, target tokens can be processed in parallel using a causal mask. During generation, outputs are produced sequentially until an end token.

Connection to T5: T5 uses an encoder–decoder Transformer architecture and a text-to-text framework. Its pretraining and implementation contain additional details, but cross-attention is the architectural idea we need here.

Part 2 — Graph Neural Networks (GNNs)

Case study: Classifying nodes in a document network

Imagine four documents connected by relationships.

Each document is represented as a node, with edges indicating some known relationship such as a citation or hyperlink.

Our task: predict a category for each document using both its own features and information from connected documents.

A simple graph

An MLP can classify nodes from their own features. But it doesn't automatically incorporate the graph structure.

A GNN adds message passing.

1. What changes inside the network?

Instead of each node processing only its own feature vector, we let it collect information from neighboring nodes.

A simple graph-convolution operation is:

hi′=ϕ(W⋅AGGREGATE⁡{hj:j∈N(i)∪{i}}+b)\boxed{ h_i'=\phi\left( W\cdot\operatorname{AGGREGATE} \{h_j:j\in\mathcal N(i)\cup\{i\}\}+b \right) }

Let's translate that into familiar terms.

Node A's feature vector

Features received from its neighbors

Aggregate: Sum / Mean / Weighted combination

Linear transformation → Activation

Updated node representation

The neural-network core remains a learned transformation.

The new idea is deciding whose information is aggregated before that transformation.

Why stack GNN layers?

One message-passing layer gathers information from immediate neighbors.

Two layers allow information to travel across two-hop neighborhoods.

0 layers

Node's own features

1 layer

Immediate neighbors

2 layers

Two-hop neighborhood

This resembles CNN receptive fields, except connectivity is defined by graph edges instead of image pixels.

The matrix formulation

A standard graph-convolution layer can be written as:

H′=ReLU⁡(A^HW+b)\boxed{H'=\operatorname{ReLU}(\hat AHW+b)}

Where:

  • HH contains node features.
  • A^\hat A is a normalized adjacency matrix describing graph connectivity, commonly including self-connections.
  • WW and bb are the learned neural-network parameters.

Tiny PyTorch example

import torch
import torch.nn as nn
import torch.nn.functional as F

# Four nodes with three features each
x = torch.randn(4, 3)

# Undirected adjacency
A = torch.tensor([
    [0., 1., 0., 1.],
    [1., 0., 1., 1.],
    [0., 1., 0., 1.],
    [1., 1., 1., 0.]
])

# Add self-connections
A = A + torch.eye(4)

# Symmetric degree normalization
degree = A.sum(dim=1)
inv_sqrt = degree.pow(-0.5)

A_norm = (
    inv_sqrt[:, None] * A * inv_sqrt[None, :]
)

# Familiar neural-network transformation
layer = nn.Linear(3, 5)

# Aggregate neighbors then apply learned weights
h = F.relu(layer(A_norm @ x))

print(h.shape)  # (4, 5)

Notice what happened:

A_norm @ x aggregates information according to the graph structure.

nn.Linear(3,5) performs the familiar learnable transformation.

We have not invented a new backpropagation algorithm. Gradients flow through the linear layer and previous GNN layers as usual.

A limitation is that deeply stacked GNNs can make different node representations overly similar, sometimes called oversmoothing. Other difficulties include extracting information from distant nodes.

Takeaway: A GNN is a neural network whose information flow follows a graph's connectivity.

1. Ordinary Autoencoder

The encoder compresses the input:

z=fθ(x)z=f_\theta(x)

The decoder reconstructs it:

x^=gϕ(z)\hat x=g_\phi(z)

We compare the reconstruction with the original:

Lreconstruction=∥x−x^∥2\boxed{L_{\text{reconstruction}}=\|x-\hat x\|^2}

For continuous pixel intensities, MSE is one possible reconstruction loss.

We train both networks end-to-end using backpropagation.

Why is this useful?

The network is encouraged to learn a representation that preserves information needed for reconstruction.

Possible applications include compression, denoising, feature extraction and anomaly detection.

But there's a limitation: an ordinary autoencoder doesn't necessarily learn a well-behaved latent space from which we can easily generate new samples.

That's one motivation for the Variational Autoencoder (VAE).

2. What does a VAE change?

Instead of mapping an image to one deterministic latent vector, a standard VAE encoder predicts parameters of a probability distribution.

Typically:

qϕ(z∣x)=N(μ(x),diag⁡(σ2(x)))\boxed{q_\phi(z\mid x)=\mathcal N(\mu(x),\operatorname{diag}(\sigma^2(x)))}

The encoder produces two vectors:

  • Mean μ\mu
  • Log-variance log⁡σ2\log\sigma^2

We sample a latent vector and feed it to the decoder.

Why reparameterization?

Remember the chain rule and backpropagation.

Directly sampling a random latent value in a naive way can obstruct differentiation through the distribution's parameters.

The reparameterization trick writes:

z=μ+σ⊙ϵ,ϵ∼N(0,I)\boxed{z=\mu+\sigma\odot\epsilon,\quad\epsilon\sim\mathcal N(0,I)}

The random noise is sampled separately, and the neural network's mean and standard deviation remain inside a differentiable computation.

VAE loss

A VAE usually has two objectives:

L=Lreconstruction+βDKL(qϕ(z∣x)∥p(z))\boxed{ L=L_{\text{reconstruction}}+ \beta D_{\mathrm{KL}}(q_\phi(z\mid x)\|p(z)) }
  • Reconstruction loss: Encourage accurate reconstruction of the input.
  • KL divergence: Encourage the learned latent distribution to remain close to a chosen prior, usually N(0,I)\mathcal N(0,I).
  • β\beta controls the relative strength; the standard VAE objective uses β=1\beta=1.

This gives us a latent space suitable for generative sampling, although sample quality depends on training and model design.

Minimal VAE code

import torch
import torch.nn as nn
import torch.nn.functional as F

class TinyVAE(nn.Module):
    def __init__(self):
        super().__init__()

        self.encoder = nn.Sequential(
            nn.Linear(784, 128),
            nn.ReLU()
        )

        self.mu = nn.Linear(128, 16)
        self.logvar = nn.Linear(128, 16)

        self.decoder = nn.Sequential(
            nn.Linear(16, 128),
            nn.ReLU(),
            nn.Linear(128, 784)
        )

    def forward(self, x):
        h = self.encoder(x)

        mu = self.mu(h)
        logvar = self.logvar(h)

        # Reparameterization trick
        eps = torch.randn_like(mu)
        z = mu + torch.exp(0.5 * logvar) * eps

        recon_logits = self.decoder(z)

        return recon_logits, mu, logvar

model = TinyVAE()

# Illustrative grayscale inputs in [0, 1]
x = torch.rand(32, 784)

recon, mu, logvar = model(x)

reconstruction_loss = F.binary_cross_entropy_with_logits(
    recon, x, reduction="none"
).sum(dim=1).mean()

kl_loss = -0.5 * (
    1 + logvar - mu.square() - logvar.exp()
).sum(dim=1).mean()

loss = reconstruction_loss + kl_loss

loss.backward()

Our output is reconstruction logits rather than digit-category logits.

Once trained, we can sample z∼N(0,I)z\sim\mathcal N(0,I) and pass it through the decoder to generate new images.

Takeaway: A VAE is an encoder–decoder neural network trained to reconstruct data while learning a probabilistically structured latent space.

Case study: Generate points from noise

This is the most conceptually different architecture of today's lesson.

Suppose we have a dataset of points arranged around a circle.

We want a model capable of generating new points with a similar distribution.

Instead of directly predicting a new sample, we introduce a gradual noise process.

The central idea is that we train a neural network to predict or remove noise, then use it repeatedly to generate data.

1. Forward diffusion — Adding noise

Take a clean sample x0x_0.

At a randomly chosen noise level tt, we construct a noisy version:

xt=αˉtx0+1−αˉtϵ\boxed{ x_t=\sqrt{\bar\alpha_t}x_0+ \sqrt{1-\bar\alpha_t}\epsilon }

Where:

  • x0x_0 is the clean data.
  • ϵ∼N(0,I)\epsilon\sim\mathcal N(0,I) is Gaussian noise.
  • αˉt\bar\alpha_t is determined by a noise schedule.
  • tt represents the noise step.

Small tt generally means relatively little noise.

Large tt generally means much more noise.

This forward process is fixed by the chosen schedule. We aren't training a network to add the noise.

2. Train a neural network to predict noise

Here's the new learning problem.

We provide the network with:

  • Noisy input xtx_t
  • Noise step tt

And ask it to predict the noise ϵ\epsilon we added.

ϵθ(xt,t)≈ϵ\boxed{\epsilon_\theta(x_t,t)\approx\epsilon}

One common loss is:

L=Ex0,t,ϵ[∥ϵ−ϵθ(xt,t)∥22]\boxed{ L=\mathbb E_{x_0,t,\epsilon} \left[\|\epsilon-\epsilon_\theta(x_t,t)\|_2^2\right] }

Notice how familiar this is.

It's just regression with MSE.

We're using a neural network to predict a vector of noise values instead of a class label.

A simple implementation

For our 2D example, an MLP is sufficient. Image diffusion systems often use U-Nets or Transformers as their denoising networks.

import torch
import torch.nn as nn
import torch.nn.functional as F

T = 100

betas = torch.linspace(0.0001, 0.02, T)
alphas = 1 - betas
alpha_bar = torch.cumprod(alphas, dim=0)

# Denoising neural network
denoiser = nn.Sequential(
    nn.Linear(3, 64),  # x, y, normalized time
    nn.SiLU(),
    nn.Linear(64, 64),
    nn.SiLU(),
    nn.Linear(64, 2)   # predicted x/y noise
)

optimizer = torch.optim.Adam(
    denoiser.parameters(), lr=0.001
)

# Toy clean data: points near a circle
B = 128
angle = torch.rand(B) * 2 * torch.pi

x0 = torch.stack([
    torch.cos(angle),
    torch.sin(angle)
], dim=1)

# Random noise steps
t = torch.randint(0, T, (B,))

# True Gaussian noise
eps = torch.randn_like(x0)

a = alpha_bar[t].unsqueeze(1)

# Create noisy data
xt = a.sqrt() * x0 + (1-a).sqrt() * eps

# Predict noise from noisy points and time
time_feature = (t.float() / (T-1)).unsqueeze(1)

predicted_noise = denoiser(
    torch.cat([xt, time_feature], dim=1)
)

loss = F.mse_loss(predicted_noise, eps)

optimizer.zero_grad()
loss.backward()
optimizer.step()

This shows one training step. To train a meaningful denoiser, we'd repeat the procedure across many batches and noise levels.

The example schedule leaves the final cumulative signal coefficient at about 0.364. Starting from standard Gaussian noise is a better approximation with a schedule whose terminal coefficient is close to zero. A complete generative model also needs the corresponding reverse sampler.

3. Inference — Reverse the process

During generation, we don't start from clean data.

We start from random noise:

Chapter 8

Summary and interview questions

Complete revision summary + 6 carefully selected, real-world interview questions

In Deep Learning Basics, we learned how neural networks work: parameters, gradients, backpropagation, optimization, regularization and generalization.

Deep Learning Architectures asks a different question:

If neural networks are universal function approximators, why do we need so many different architectures?

Why use CNNs for images, RNNs for sequences, Transformers for language, GNNs for graphs and diffusion models for generation?

The answer lies in how information is structured.

Different architectures make different assumptions about which relationships matter. These assumptions are called inductive biases.

An architecture that captures the right structure can learn useful patterns with less data, fewer parameters or more effective computation.

This is the central idea connecting everything in Deep Learning Architectures.

Part I — The complete conceptual summary

From fully connected networks to specialized architectures

A fully connected neural network treats an input as a collection of numerical features.

Suppose we have a 256×256 RGB image.

Flattening it produces: 256×256×3=196,608256\times256\times3=196{,}608

input values.

A fully connected layer with 1,000 output neurons would require approximately 197 million weights.

But this architecture ignores something fundamental about images.

Pixels have spatial relationships.

Nearby pixels often form edges, textures and shapes. A feature detected in the top-left corner might also be useful in the bottom-right corner.

A fully connected network doesn't naturally exploit either property.

This motivates the first architecture we studied: convolutional neural networks.

The same principle applies elsewhere.

Language contains ordered relationships between tokens. Graphs contain explicit relationships between entities. Images contain local spatial structure.

Architecture design is fundamentally about deciding how information should interact.

CNNs — Learning spatial patterns through shared filters

A Convolutional Neural Network uses small filters that slide across an image.

Instead of learning a separate feature detector at every image location, the network reuses the same filter everywhere.

For example, a 3×3 filter might learn to detect vertical edges.

Applied across the image, it produces a feature map showing where those edges occur.

This gives CNNs two powerful properties.

Local connectivity: Early layers primarily examine nearby pixels.

Parameter sharing: A filter uses the same learned weights across spatial positions.

Suppose an input has three channels and a convolutional layer has 64 filters of size 3×3.

Ignoring biases, the layer requires: 64×3×3×3=1728 weights64\times3\times3\times3=\boxed{1728\text{ weights}}

This is dramatically smaller than a large fully connected layer.

The convolutional layer also preserves the spatial arrangement of its output features. Why does depth matter in CNNs? Early convolutional layers may detect simple patterns such as edges and textures.

Later layers combine earlier features into more complex representations.

A useful mental model is:

Pixels → Edges → Textures → Parts → Objects.

This isn't a rigid rule that every CNN follows, but it captures hierarchical feature composition. Stride, padding and pooling Stride determines how far the convolutional filter moves between positions.

Larger strides reduce the spatial resolution of feature maps.

Padding controls how image boundaries are handled and influences output dimensions.

Pooling summarizes local regions, reducing resolution and sensitivity to certain small spatial changes.

These operations help manage computation and build increasingly abstract features.

But downsampling has a cost.

If you're detecting tiny cracks in manufactured components, aggressively reducing image resolution may destroy the very information you need. Translation equivariance versus invariance This is an important interview distinction.

Convolution is approximately translation equivariant under the appropriate boundary conditions.

If an object shifts within an image, its corresponding feature-map response tends to shift.

That's not the same as translation invariance.

Invariance means the final output remains unchanged under a transformation.

Pooling, global aggregation, data augmentation and learned representations can help produce useful invariance.

Key insight: CNNs are effective because they encode locality and weight sharing, not because they automatically understand objects.

RNNs — Introducing memory into neural networks

Images have spatial structure.

But sequences have another property: order.

Consider:

"The dog chased the cat."

and:

"The cat chased the dog."

The words are almost identical, but their ordering changes the meaning.

A simple feed-forward network doesn't naturally maintain a state that evolves as sequential inputs arrive.

A Recurrent Neural Network addresses this by reusing a hidden state. ht=ϕ(Wxxt+Whht−1+b)\boxed{h_t=\phi(W_xx_t+W_hh_{t-1}+b)}

Where: - xtx_t is the current input. - ht−1h_{t-1} is the previous hidden state. - hth_t is the updated state. The network processes one timestep at a time.

Its hidden state carries a compressed representation of what it has encountered. What is actually recurrent? The same weight matrices are reused at every timestep.

That's important.

We don't learn a completely new network for every position in the sequence.

Instead, we repeatedly apply the same transformation while updating the state.

This lets RNNs process variable-length sequences. Backpropagation Through Time During training, the recurrence is unrolled across timesteps.

Gradients flow backward through these repeated computations.

This is called Backpropagation Through Time (BPTT).

The problem is that gradients must pass through many recurrent transitions.

Repeated multiplication by recurrent Jacobians can cause gradients to shrink or grow dramatically.

Consequently, vanilla RNNs often struggle with long-term dependencies.

Consider:

"The book that I borrowed from my friend several weeks ago ... was fascinating."

The network may need to preserve information across many intervening words to make a correct prediction.

A vanilla RNN can struggle to maintain that information.

This motivates LSTMs and GRUs.

LSTMs and GRUs — Learning what to remember and forget

An LSTM is a recurrent architecture designed to make long-range information preservation easier.

Its central idea is a cell state that carries information through time.

Gates control how the state changes.

The main LSTM gates are:

Forget gate: Determines which existing information should be retained.

Input gate: Determines which new information should be written.

Output gate: Determines which information from the updated cell state influences the hidden output.

A simplified cell-state update is: ct=ft⊙ct−1+it⊙c~t\boxed{c_t=f_t\odot c_{t-1}+i_t\odot\tilde c_t}

Where: - ftf_t controls retention. - iti_t controls new information. - c~t\tilde c_t is candidate information. - ⊙\odot is element-wise multiplication. The important feature is the additive state update.

Unlike repeatedly replacing the state through an ordinary nonlinear transformation, this creates pathways that can preserve information and support better gradient propagation. An intuitive example Suppose an LSTM is reading a product review.

The review begins:

"I bought this laptop last month..."

Later, it says:

"Despite the beautiful screen, the battery life is disappointing."

The network must update its representation as new information appears.

It may retain the product being discussed while changing its assessment of the review's sentiment.

The gates provide a learned mechanism for controlling information flow. GRU versus LSTM A Gated Recurrent Unit uses a simpler gating structure.

It combines some of the roles handled by separate LSTM gates and doesn't maintain the same separate cell-state representation.

GRUs often have fewer parameters than comparable LSTMs.

Neither is universally superior.

An LSTM may be useful when more flexible memory control helps; a GRU may offer similar performance with lower complexity for some tasks. Do LSTMs solve all long-range dependencies? No.

They improve recurrent memory and gradient flow, but information is still compressed into a finite-dimensional state.

They also retain an important computational limitation:

Timesteps depend sequentially on previous timesteps.

This limits parallelization across sequence positions during a single forward pass.

That limitation becomes important when comparing RNNs with Transformers.

Encoder–decoder models — From understanding a sequence to generating another

Let's imagine a machine-translation problem.

Input:

"The weather is beautiful today."

Output:

"Das Wetter ist heute schön."

The input and output have different token sequences and potentially different lengths.

An encoder–decoder architecture handles this transformation.

The encoder processes the input sequence into useful representations.

The decoder generates the output sequence.

Early sequence-to-sequence systems often used recurrent encoders and decoders.

The encoder compressed the input into a fixed-size representation, commonly its final hidden state.

The decoder used that representation to generate the translation.

But there's a serious problem. The fixed-vector bottleneck Suppose we need to translate a 300-word paragraph.

Compressing every relevant detail into one fixed-dimensional vector is difficult.

Names, grammatical relationships, long-distance dependencies and specific content may be lost.

The decoder also needs different pieces of the input at different output positions.

When generating a German noun, it may need to focus on one source word.

When generating the corresponding verb, it may need information from another part of the source sentence.

This motivates attention.

Attention — Let the model retrieve relevant information dynamically

Attention changes how a sequence model accesses information.

Instead of depending exclusively on one compressed state, the decoder can examine representations of all source positions.

For each decoding step, it calculates relevance scores over the encoder states and forms a weighted combination.

Conceptually: ct=∑iαt,ihi\boxed{c_t=\sum_i\alpha_{t,i}h_i}

Where: - hih_i is the representation of source position ii. - αt,i\alpha_{t,i} is the attention weight for that position. - ctc_t is the context vector used by the decoder. The attention weights are generally normalized to sum to one. Why is this powerful? Consider translating:

"The student who studied in Germany passed the exam."

When generating the translated word corresponding to "student," the decoder may need to focus on one part of the source.

When generating "exam," it may need a different part.

Attention allows the model to access information dynamically rather than forcing every detail through one bottleneck.

This was a major development in sequence modeling.

But attention later became even more important.

Instead of attaching attention to recurrent networks, researchers built architectures in which attention itself became the central mechanism.

That leads to Transformers.

Self-attention and the Transformer — Learning relationships between all tokens

The Transformer replaces the fundamental recurrence of RNN-based sequence modeling with attention-based interactions between positions.

The central mechanism is scaled dot-product attention: Attention⁡(Q,K,V)=softmax⁡(QK⊤dk+M)V\boxed{ \operatorname{Attention}(Q,K,V) = \operatorname{softmax}\left( \frac{QK^\top}{\sqrt{d_k}}+M \right)V }

The three projections serve different conceptual roles.

Query: What information is this position looking for?

Key: What information does each position offer for matching?

Value: What information should be retrieved and combined?

Each input representation is projected into query, key and value vectors.

The model compares queries with keys to determine attention weights, then combines value vectors according to those weights. A concrete language example Consider:

"The animal didn't cross the road because it was tired."

For the token "it," useful information may be found in the representation of "animal."

Self-attention allows the model to connect these positions directly.

In a recurrent network, information from the earlier token must travel through intermediate recurrent states.

In a Transformer, attention can connect distant positions in one attention operation.

That doesn't mean attention automatically understands pronoun references. It means the architecture provides an efficient mechanism for learning such relationships. Multi-head attention Instead of calculating one attention pattern, the network uses several attention heads.

Different heads can learn different relationships or representation transformations.

One head might emphasize local syntactic patterns, another might capture longer-distance dependencies, and another might learn less easily interpretable statistical relationships.

These examples are illustrative; attention heads are not guaranteed to specialize neatly.

The outputs of the heads are combined through a learned projection. Why positional information is necessary Without positional information, ordinary self-attention doesn't inherently know the sequence ordering.

Tokens are represented as content vectors, and attention operates on relationships between those representations.

Position encodings or embeddings introduce information about token order.

Our later LLM volume explored RoPE as a modern positional method. Why are Transformers so efficient to train? Unlike a standard RNN, self-attention over known input positions can be computed largely in parallel using matrix operations.

This makes Transformers highly suitable for GPU and TPU acceleration.

However, ordinary full self-attention creates interactions across pairs of positions.

Its attention-score computation scales approximately quadratically with sequence length: O(T2)O(T^2)

So Transformers trade recurrence-related sequential computation for a different challenge: expensive attention over long contexts.

This helps explain both their success and the long-context engineering techniques we studied in Modern LLMs.

Encoder-only Transformers — Understanding a complete input

Encoder-only architectures, such as BERT, use bidirectional self-attention.

A token can attend to both earlier and later positions in the input.

This is particularly useful when the entire input is available before making a prediction.

Imagine classifying a customer review:

"The battery was initially disappointing, but after the update it became excellent."

The meaning of the review depends on both earlier and later context.

A bidirectional encoder can build representations using the full sentence.

Encoder-only models are commonly used for classification, token labeling, embeddings, reranking and other representation-oriented tasks. Pretraining and fine-tuning The original BERT uses Masked Language Modeling.

Some input tokens are hidden, and the model learns to predict the missing tokens from surrounding context.

This is different from GPT-style causal language modeling.

After pretraining, the encoder can be adapted to downstream tasks.

For classification, we might use a pooled representation.

For token labeling, we use representations associated with individual tokens.

For sentence embeddings, we need an appropriate pooling or embedding-training strategy.

An important distinction:

A pretrained BERT checkpoint doesn't automatically produce optimal semantic sentence embeddings simply because it is bidirectional.

Specialized contrastive or other embedding training can substantially improve retrieval performance.

Decoder-only Transformers — Predicting and generating continuations

Decoder-only architectures, such as GPT, use causal self-attention.

At position tt, the model can access previous positions but not future ones.

This enables autoregressive language modeling: P(x1,…,xT)=∏t=1TP(xt∣x<t)\boxed{ P(x_1,\ldots,x_T)= \prod_{t=1}^{T}P(x_t\mid x_{<t}) }

The model learns to predict each next token from the preceding sequence.

During training, all known target positions can contribute to the loss in parallel under a causal mask.

During generation, new tokens must ordinarily be produced sequentially because each depends on preceding generated tokens.

This distinction is central.

Causal masking does not prevent parallel processing of known sequences during training. It prevents attention to future positions.

Decoder-only models are particularly convenient for open-ended generation, dialogue, code generation and tasks formulated as text continuation.

They can also solve classification and extraction tasks by generating labels or structured responses.

But that doesn't automatically make them the most efficient architecture for every task.

For a simple text-classification problem with labeled data, a smaller encoder may be cheaper and just as effective.

Encoder–decoder Transformers — Understanding one sequence while generating another

The third major Transformer family combines an encoder and decoder.

Examples include T5-style and BART-style architectures.

The encoder processes the entire source sequence bidirectionally.

The decoder generates output tokens causally.

Crucially, the decoder can also attend to encoder representations through cross-attention.

The three attention mechanisms are:

Encoder self-attention: Input tokens interact with each other.

Decoder causal self-attention: Generated tokens interact with earlier generated tokens.

Decoder cross-attention: Output positions retrieve information from the input representations.

Suppose we're summarizing a scientific paper.

The encoder creates representations of the paper.

The decoder generates the summary while cross-attending to those representations.

This architecture explicitly separates source understanding from output generation. Encoder-only versus decoder-only versus encoder–decoder Architecture Attention access Natural strength Encoder-only Both directions within the input Representation learning and understanding tasks Decoder-only Previous positions only Autoregressive generation Encoder–decoder Bidirectional source + causal target + cross-attention Conditional sequence generation

This isn't a strict boundary of what each architecture can achieve.

It's a useful architectural distinction for choosing efficient solutions.

A common interview mistake is to claim that encoder-only models cannot generate any text or that decoder-only models cannot classify text.

The more accurate question is which architecture and objective are most appropriate for the desired task.

Graph Neural Networks — Learning from relationships, not sequences

Until now, our architectures mainly handled fixed-dimensional features, spatial grids or sequences.

But many real-world datasets are graphs.

Examples include: - Social networks. - Molecular structures. - Citation networks. - Knowledge graphs. - Transportation systems. - Relations between claims and evidence. A graph contains nodes and edges.

A Graph Neural Network learns node representations by combining information from neighboring nodes.

A general message-passing layer can be written as: hv(l+1)=Update⁡(hv(l),Aggregate⁡u∈N(v)Message⁡(hu(l),hv(l),euv))\boxed{ h_v^{(l+1)} = \operatorname{Update}\left( h_v^{(l)}, \operatorname{Aggregate}_{u\in N(v)} \operatorname{Message}(h_u^{(l)},h_v^{(l)},e_{uv}) \right) }

This may look complicated, but the intuition is straightforward.

Each node updates its representation using information from connected nodes. Example: A citation network Suppose each scientific paper is a node.

Edges represent citations.

Each paper also has a text embedding.

A GNN can combine a paper's textual features with representations of related papers.

If the citation structure contains useful information about research topics, this may improve classification. Why is graph structure useful? Two nodes may have similar features but different structural roles.

Conversely, nodes with very different initial features might belong to similar neighborhoods.

GNNs allow relationships to influence learned representations. What happens when we stack GNN layers? With one message-passing layer, a node generally receives information from immediate neighbors.

With two layers, it can receive information that originated two hops away.

And so on.

But deeper isn't automatically better.

A major issue is oversmoothing.

Repeatedly aggregating neighborhood representations can make node embeddings increasingly similar, reducing their ability to distinguish different nodes.

Other problems include oversquashing, where too much information must pass through limited representational bottlenecks, and difficulty when neighboring nodes tend to have dissimilar labels or features. GNNs also introduce graph-specific data leakage Suppose we're predicting missing edges in a graph.

If the graph used for message passing already contains the edges we're supposed to predict, evaluation may be invalid.

Likewise, train/test separation must be designed around the task.

A node-classification benchmark may legitimately use a shared graph with masked test labels, whereas inductive evaluation on unseen graphs has different requirements.

Graph splitting isn't just ordinary random row splitting. The topology itself can carry information.

Autoencoders — Learning useful compressed representations

An autoencoder learns to reconstruct its input.

It consists of:

Encoder: z=fθ(x)z=f_\theta(x)

Decoder: x^=gϕ(z)\hat x=g_\phi(z)

The training objective usually measures reconstruction error: L=ReconstructionLoss⁡(x,x^)L=\operatorname{ReconstructionLoss}(x,\hat x)

The latent representation zz can be lower-dimensional than the original input.

For example, a 1,000-dimensional input may be compressed into a 32-dimensional latent vector.

If the model reconstructs useful patterns from this bottleneck, it must preserve information relevant to reconstruction. Why doesn't an autoencoder simply copy everything? A sufficiently powerful model with an unconstrained representation may learn a near-identity mapping.

So meaningful representation learning generally requires constraints.

These might include a smaller latent bottleneck, sparsity, noise corruption or regularization. Anomaly detection Suppose an autoencoder is trained primarily on normal industrial sensor readings.

It may learn to reconstruct normal patterns well.

An abnormal reading could produce a larger reconstruction error.

That makes reconstruction error a possible anomaly score.

But this isn't guaranteed.

A powerful autoencoder may also reconstruct unusual inputs well.

And a normal but rare example might have high reconstruction error.

Therefore, anomaly detection quality must be evaluated independently.

Variational Autoencoders — Learning a structured latent distribution

A Variational Autoencoder (VAE) extends the autoencoder idea.

Instead of mapping each input directly to one deterministic latent vector, its encoder predicts parameters of a distribution over latent variables.

Typically: qϕ(z∣x)q_\phi(z\mid x)

The decoder models the reconstruction distribution: pθ(x∣z)p_\theta(x\mid z)

Training balances reconstruction quality against how much the approximate posterior differs from a prior distribution.

A common objective is: L=Lreconstruction+βDKL(qϕ(z∣x)∥p(z))\boxed{ L= L_{\mathrm{reconstruction}} + \beta D_{\mathrm{KL}}(q_\phi(z\mid x)\|p(z)) }

The KL term encourages the latent distribution to have a useful structure relative to the chosen prior.

This can make it easier to sample latent vectors and generate new outputs. Why use a VAE instead of an ordinary autoencoder? An ordinary autoencoder can compress and reconstruct data, but its latent space may not be well behaved for random sampling.

A VAE explicitly trains a probabilistic latent representation.

This supports generative modeling and interpolation.

However, VAEs can face trade-offs between reconstruction sharpness, likelihood modeling and latent regularization.

The key distinction is:

An autoencoder learns a reconstruction mapping. A VAE learns a probabilistic generative model with a structured latent space.

Diffusion models — Generate by learning to remove noise

Our final generative architecture was diffusion.

Instead of generating an image directly from a latent vector in one step, diffusion models typically learn a gradual reverse process.

During the forward noising process, noise is added to training examples.

At a given timestep: xt=αˉtx0+1−αˉtϵx_t=\sqrt{\bar\alpha_t}x_0+ \sqrt{1-\bar\alpha_t}\epsilon

Where x0x_0 is the clean sample and ϵ\epsilon is sampled noise.

A neural network is trained to predict noise, a clean sample or another related target, depending on the formulation.

A common noise-prediction objective is: L=E[∥ϵ−ϵθ(xt,t,c)∥2]\boxed{ L=\mathbb E\left[ \|\epsilon-\epsilon_\theta(x_t,t,c)\|^2 \right] }

Here cc can represent conditioning information, such as a text prompt.

During generation, we begin with noise and progressively transform it toward a sample from the learned data distribution. Why does this work? The model doesn't need to generate a complete high-quality image in a single transformation.

It learns how to move noisy inputs toward more plausible data across different noise levels.

The reverse generation process repeatedly applies the learned denoising behavior. What architecture performs denoising? Diffusion is a generative modeling framework, not one fixed neural-network architecture.

The denoiser might be a U-Net or a Transformer-based architecture.

This is an important distinction.

CNNs and Transformers define ways of processing information.

Diffusion defines a family of generative processes and training objectives. Why is diffusion generation computationally expensive? Traditional diffusion sampling requires multiple denoising steps.

Each step performs neural-network computation.

That can make generation slower than a single forward pass.

Modern samplers, distillation and alternative formulations can reduce the required steps, with quality and speed trade-offs. The generative-model distinction An ordinary autoencoder primarily learns reconstruction.

A VAE learns a probabilistic latent-variable model.

A diffusion model learns a process that transforms noise toward data.

These architectures can overlap: latent diffusion systems, for example, combine autoencoder-based compression with diffusion in latent space.

Part II — Six real-world interview questions

These questions are designed to test whether you can choose, diagnose and reason about architectures, not just explain their definitions.

Question 1 — A CNN performs poorly on tiny defects

Scenario: You're building a visual inspection system for industrial components. Your CNN accurately identifies large scratches but consistently misses tiny cracks.

You increase the network's depth, but performance barely improves.

Why might this happen? Would a larger model solve the problem?

Answer:

My first suspicion would be information loss, not insufficient model depth.

If the network uses aggressive downsampling, a crack that occupies only a few pixels may disappear from the feature maps before deeper layers can analyze it.

Increasing depth doesn't recover spatial information that has already been discarded.

I'd inspect input resolution, early convolutional strides, pooling operations and the size of defects relative to feature-map resolution.

Possible solutions include preserving higher-resolution feature maps, using smaller early strides, multi-scale architectures and training crops that preserve fine details.

I'd also examine annotation quality and whether the training set contains enough representative tiny defects.

A larger network might help if representational capacity is the bottleneck, but it won't automatically solve a resolution problem.

Interview principle: Before increasing model capacity, check whether the architecture preserves the information needed for the task.

Question 2 — Why might an LSTM be preferable to a Transformer?

Scenario: You're building a system that processes sensor readings from industrial equipment.

A new reading arrives every 10 milliseconds. The system must continuously update its prediction with limited memory and low latency.

Would you automatically choose a Transformer because it is a more modern architecture?

Answer:

No.

The requirements favor efficient sequential state updates.

An LSTM or GRU can maintain a fixed-dimensional hidden state and update it as each new reading arrives.

It doesn't necessarily need to repeatedly process the entire history.

A standard full-attention Transformer may require retaining and accessing a growing history of representations, unless we impose a bounded context or use another memory mechanism.

The Transformer might capture certain long-range dependencies more effectively, particularly if there are complex relationships across distant timesteps.

But the relevant engineering questions are whether those dependencies matter, how large the required history is, and whether the model meets latency and memory constraints.

I'd benchmark a small GRU, a temporal convolutional network and a suitable Transformer variant rather than choosing based on popularity.

Interview principle: Architectural sophistication isn't the objective. Matching the workload's temporal structure and constraints is.

Question 3 — Attention helps translation, but what problem does it actually solve?

Scenario: You train an RNN encoder–decoder translation model.

It translates short sentences reasonably well, but performance deteriorates sharply on long sentences.

You add an attention mechanism and performance improves.

Why?

Answer:

The original encoder–decoder had to compress the source sentence into a limited representation.

As sentences became longer, preserving every relevant detail became increasingly difficult.

Attention gives the decoder access to the encoder's representations at multiple source positions.

At each output step, it can construct a context vector based on the source information currently needed.

This reduces reliance on a single fixed-size summary.

For example, when translating a particular noun, the decoder can emphasize its source representation rather than hoping that the encoder's final hidden state preserved every relevant detail.

However, adding attention doesn't eliminate the RNN decoder's sequential dependence.

Nor does attention guarantee perfect alignment or translation.

It addresses the information-access bottleneck, while other architectural limitations may remain.

Interview principle: Attention allows dynamic access to information. Its importance goes beyond simply assigning weights to words.

Question 4 — BERT, GPT or T5: Which would you choose?

Scenario: You're building three separate NLP systems:

A. Classify scientific abstracts into research categories.

B. Generate detailed explanations of experimental results.

C. Translate technical English documents into German.

Which architecture would you consider for each, and why?

Answer:

For A, I'd start with an encoder-only Transformer such as a BERT-family model.

The entire abstract is available, and the main objective is to construct a useful representation for classification.

Bidirectional self-attention fits naturally.

For B, I'd consider a decoder-only instruction-tuned model.

The task requires open-ended conditional generation, and autoregressive decoding is a natural fit.

For C, an encoder–decoder model such as a T5-style system is particularly well suited to conditional sequence transformation.

The encoder represents the source document, and the decoder generates the translated sequence using cross-attention.

However, these aren't exclusive choices.

A decoder-only LLM can perform classification and translation by generating outputs, and a sufficiently strong model may outperform a smaller specialized architecture.

The decision should account for labeled data availability, evaluation quality, inference cost, deployment constraints and the need for open-ended generation.

Interview principle: Encoder-only, decoder-only and encoder–decoder architectures differ in information flow and training objectives, not in rigid rules about which tasks they're allowed to perform.

Question 5 — A deeper GNN performs worse than a shallow GNN

Scenario: You're classifying papers in a citation network.

A two-layer GNN performs well.

You increase it to eight message-passing layers, expecting it to use more distant citation information.

Instead, accuracy deteriorates and many node embeddings become increasingly similar.

Why?

Answer:

One likely explanation is oversmoothing.

Each message-passing layer aggregates information from neighboring nodes.

As we repeatedly mix neighboring representations, nodes in connected regions can become more similar.

Eventually, representations may lose information that distinguishes individual classes or structural roles.

Increasing neighborhood reach also introduces irrelevant or noisy information.

I'd compare embedding similarity across layers, inspect how accuracy changes with depth, and examine whether the graph's relationships actually support the classification task.

Possible interventions include residual connections, normalization, controlling neighborhood aggregation, jumping-knowledge architectures or simply using fewer layers.

I'd also examine the graph structure.

If papers connected by citations often belong to different categories, indiscriminate neighbor averaging may be counterproductive.

Finally, I'd carefully verify the data split. Graph structure can unintentionally leak evaluation information if the task and split protocol are not designed correctly.

Interview principle: More message-passing layers don't necessarily mean more useful relational information. Graph structure, aggregation and evaluation design determine whether deeper propagation helps.

Question 6 — Autoencoder, VAE or diffusion model?

Scenario: You're working with a manufacturing company.

They have two objectives:

A. Detect unusual sensor patterns.

B. Generate realistic synthetic examples of normal operating conditions.

Would you use the same generative architecture for both tasks?

Answer:

Not necessarily.

For A, I'd first consider an autoencoder trained on representative normal sensor sequences.

Reconstruction error could serve as an anomaly score.

But I'd verify that abnormal patterns actually produce distinguishable errors. A powerful autoencoder may reconstruct some anomalies well, while unusual-but-normal examples may produce false alarms.

Depending on the dataset, a predictive sequence model or other density/anomaly method might be more effective.

For B, I'd consider a probabilistic generative model.

A VAE can learn a structured latent representation from which new samples can be generated.

A diffusion model may provide another approach, particularly when the target distribution is complex and sample quality matters.

But generating visually or statistically plausible sensor sequences doesn't guarantee that they obey the real system's physical constraints.

I'd evaluate generated samples using statistical properties, temporal consistency, domain-specific constraints and downstream usefulness.

The same model family could potentially support both objectives, but the optimization targets and success criteria differ.

Interview principle: Reconstruction quality, anomaly detection and realistic generation are related but distinct objectives. Choose the modeling and evaluation strategy for the actual task.

The six principles to remember from Deep Learning Architectures 1. Architecture is an inductive bias. Different networks encode different assumptions about how information is related.

  1. CNNs exploit spatial locality and parameter sharing. Their efficiency comes from structure, not simply from having convolution operations.

  2. Recurrent networks maintain evolving state. LSTMs and GRUs improve information retention, but sequential computation remains a defining characteristic.

  3. Attention provides dynamic information access. Transformers build on this to model token relationships efficiently through parallel computation.

  4. Encoder, decoder and encoder–decoder Transformers solve different information-flow problems. Their suitability depends on the objective and computational constraints.

  5. Graph and generative architectures address different representations and objectives. GNNs model explicit relationships; autoencoders learn reconstruction-based representations; VAEs and diffusion models provide different approaches to generative modeling.
