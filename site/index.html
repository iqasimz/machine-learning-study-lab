Machine Learning Study Lab

Learn how models work, train them locally and understand what their results actually show.

Machine Learning Study Lab brings together courses in machine learning, deep learning, natural language processing and large language models. It connects the ideas behind a method to its calculations, implementation choices and evaluation: what goes in, what changes inside the model, what comes out, and how to tell whether it worked.

Lessons combine plain-language explanations, equations, worked examples and original sources. Selectable diagrams let you inspect a component’s purpose, inputs, outputs and connections. The training labs let you change settings, run local experiments, inspect saved results and compare models. Some advanced methods are taught but do not have an executable trainer here; NLP currently has worked calculations rather than a dedicated training lab. Opening a lesson never starts training.

Loss on training and held-out text
Loss is an average negative log probability of correct targets. Training text supplies updates; development text selects a checkpoint, a saved set of weights. An update is one optimizer step, not one example.
Read the axis units first, then compare the training and development curves at matched progress. Falling training loss with worsening development loss can indicate overfitting. Inspect the recorded values before deciding to continue training.
Each point is a recorded observation. Loss on the vertical axis is an average guessing penalty. A token practised twice counts twice on the token axis.

Training text and tokenization
A token is a tokenizer-defined text piece; its ID names a vocabulary entry. A split assigns documents to training, development or test.
Choose a source document, inspect its text and tokenize an example with this run’s actual tokenizer. Those IDs become model inputs; the next subsection shows how shifted targets are constructed. Token IDs are not probabilities.
This uses the run's actual tokenizer. Numbers below the pieces are vocabulary IDs, not probabilities.
Next-token targets
For next-token training, the answer is the next piece already present in the text. The input is shifted by one position to create targets. In adapter training, only assistant responses contribute to the loss; user instructions do not.


Checkpoint calculations
An embedding represents a token as a vector. Attention weights mix permitted positions. Logits are raw output scores; probabilities normalize those scores. A gradient measures loss sensitivity to a parameter.
Enter short text and load the saved checkpoint for a read-only forward calculation. Inspect embeddings, attention and next-token scores in that order. Attention rows are reading positions; columns are positions they can use. Darker cells mean larger mixing weights, not more truthful explanations.
The update inspector uses one short batch and SGD at 0.01 on a disposable copy. It does not replay the original training run or change saved weights. Available for scratch models below five million parameters.
The attention diagram in Model diagrams explains the arithmetic. This view shows actual saved-model values, with token and dimension limits.


Text generation
A prompt is the starting text. Temperature changes the sharpness of token probabilities; top-k limits candidate tokens; a seed initializes sampling randomness.
The checkpoint turns the prompt into scores. Decoding converts them into a selected token, appends it to the input and repeats until the stop rule or output limit. None of these controls retrains weights.


Baseline and checkpoint scores
These scores measure prediction of the supplied reference text. Lower loss is better on matching targets; perplexity is an exponential form of that loss, not an accuracy percentage. Read the sample responses as a separate check of usefulness and factual errors.
